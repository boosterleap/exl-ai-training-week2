Why MCP exists

Without a shared protocol, every AI host re-implements every tool integration. That is an N × M problem (N hosts × M systems). MCP collapses it to one contract: JSON-RPC messages for list tools / call tool / read resources / get prompts. 

User
  │
  ▼
AI Host (Cursor, Claude Desktop, your agent CLI)
  │  MCP client session
  │  JSON-RPC over stdio or Streamable HTTP
  ▼
MCP Server (inventory, ops, filesystem, …)
  ├── Tools      (do work)
  ├── Resources  (read-only data)
  └── Prompts    (reusable templates)
Day 2 lab mapping Learners run a local inventory MCP server; enterprise CRM/ERP connectors stay concept-only (Salesforce Agentforce, ServiceNow, SAP). See instructor guide Day 2 PM topics 02–04.

Host · client · server

RoleWhat it isWeek 2 example
Host The AI application the user talks to. Owns UX, model calls, permissions, sessions. Claude Agent SDK CLI, LangGraph runner, Cursor
Client Protocol speaker inside the host. Opens a session, initializes, lists/calls tools. ClientSession + streamablehttp_client
Server Process that exposes tools/resources/prompts. May be in-process or a separate HTTP process. inventory_server.py on 127.0.0.1:8765

Colloquially people say “MCP client” for the whole host. In the spec, the host embeds one or more clients, each talking to a server.

MCP ≠ A2A MCP connects agent → tool/server. A2A connects agent → agent (Agent Cards). Module 10 covers A2A. Together they form the Day 2 integration story.

Transports — in-process vs Streamable HTTP

ModeHow it runsWhen Week 2 uses it
In-process / SDK MCP Server object lives inside the host process. Tools registered via SDK helpers (e.g. Day 1 mcp_servers={{"ops": ...}}). Day 1 insurance/banking/logistics tools — no open port.
stdio Host spawns server.py as a subprocess; JSON-RPC on stdin/stdout. Default mcp.run(). Claude Desktop, MCP Inspector (uv run mcp dev server.py).

Tool naming: mcp__<server>__<tool>

Claude Agent SDK surfaces MCP tools with a fixed prefix so the model (and your allowed_tools / permission gates) can address them unambiguously: 

mcp__<server_key>__<tool_name>

# Day 1 ops server (in-process)
mcp__ops__policy_lookup
mcp__ops__claims_status

# Day 2 inventory server (if wired into an SDK host as key "inventory")
mcp__inventory__get_stock
mcp__inventory__list_low_stock

The middle segment is the key you pass in mcp_servers={{"ops": ...}} or the FastMCP server name as configured by the host — not the Python function’s module path. Permission gates often strip with tool_name.rsplit("__", 1)[-1] to recover the short tool name.

Exercise I3 · Simulate content blocks

MCP clients often receive tool results as content blocks with a .text field holding JSON. Parse like Day 2 W2D2/W2D2PM/d2pmt2c02_mcp_client.py. 

import json
from types import SimpleNamespace

def parse_mcp_result(result) -> dict:
  text_blocks = []
  for block in result.content:
    text = getattr(block, "text", None)
    if text:
      text_blocks.append(text)
  raw = text_blocks[0] if text_blocks else "{}"
  try:
    payload = json.loads(raw)
  except json.JSONDecodeError:
    payload = {"raw": raw}
  if isinstance(payload, dict):
    payload["source"] = "mcp_server"
  return payload

fake_result = SimpleNamespace(
  content=[SimpleNamespace(text=json.dumps({"found": True, "sku": "SKU-3002", "qty_on_hand": 45}))]
)
parsed = parse_mcp_result(fake_result)
assert parsed["source"] == "mcp_server"
assert parsed["qty_on_hand"] == 45
print(parsed)

FastMCP inventory server sketch (June 2026)

"""Conceptual companion to Week2/W2D2/W2D2PM/d2pmt2c01_mcp_server.py"""
from __future__ import annotations
import json
from pathlib import Path
from mcp.server.fastmcp import FastMCP

WEEK2_ROOT = Path(__file__).resolve().parents[1]
INVENTORY_PATH = WEEK2_ROOT / "data" / "supply" / "inventory.json"

mcp = FastMCP("inventory", host="127.0.0.1", port=8765)

def load_inventory() -> dict:
  return json.loads(INVENTORY_PATH.read_text(encoding="utf-8"))

@mcp.tool()
def get_stock(sku: str) -> dict:
  """Return on-hand quantity and location for one SKU."""
  payload = load_inventory()
  for item in payload["items"]:
    if item["sku"] == sku:
      return {"found": True, "warehouse": payload["warehouse"], **item}
  return {"found": False, "sku": sku}

@mcp.tool()
def list_low_stock() -> dict:
  """Return items at or below the reorder point."""
  payload = load_inventory()
  low = [i for i in payload["items"] if i["qty_on_hand"] <= i["reorder_point"]]
  return {"warehouse": payload["warehouse"], "count": len(low), "items": low}

if __name__ == "__main__":
  mcp.run(transport="streamable-http")

Client call sketches (June 2026 Python SDK)

Patterns below match the Week 1 MCP quick reference and Day 2 tools._mcp_call_tool. Requires the server running — use offline fakes above when the port is closed.

Streamable HTTP client

import asyncio
import json
from mcp import ClientSession
from mcp.client.streamable_http import streamablehttp_client

MCP_URL = "http://127.0.0.1:8765/mcp"

async def call_get_stock(sku: str) -> dict:
  async with streamablehttp_client(MCP_URL) as streams:
    read_stream, write_stream, _get_session_id = streams
    async with ClientSession(read_stream, write_stream) as session:
      await session.initialize()
      tools = await session.list_tools()
      print([t.name for t in tools.tools])
      result = await session.call_tool("get_stock", {"sku": sku})
      text = next(b.text for b in result.content if getattr(b, "text", None))
      return json.loads(text)

Advanced Advanced

Auth · SSO · API gateways (concept)

The classroom inventory server has no auth — it binds localhost only. Enterprise MCP deployments typically put a front door in front of servers:

LayerRoleLearner takeaway
SSO / IdP Who is calling (employee, service principal). Host presents tokens; servers trust the gateway’s identity claims.
API gateway TLS termination, rate limits, routing to MCP endpoints, audit logs. Clients talk to the gateway URL, not raw warehouse systems.
Scoped credentials Per-tool or per-resource permissions (read stock vs release hold). Same idea as Day 1 write-tool approval — policy outside the model.
Registry / catalog Discover approved servers (ecosystem scale: thousands of servers / many SDKs). Lab skips registry; production does not hard-code every URL in agents. 
mcp_deployment_notes = {
  "in_process": "Day 1 custom tools inside the agent process",
  "network_streamable_http": "Day 2 inventory_server.py on 127.0.0.1",
  "enterprise_front_door": ["SSO", "API gateway", "scoped credentials"],
}

Exercise A2 · Dry-run vs MCP source tag

Day 2 helpers tag source: local_file vs source: mcp_server. Implement a tiny router offline. 

def get_stock_routed(sku: str, use_mcp: bool, payload: dict) -> dict:
  base = get_stock(sku, payload)
  if use_mcp:
    # pretend network succeeded — same data, different provenance
    return {**base, "source": "mcp_server"}
  return {**base, "source": "local_file"}

a = get_stock_routed("SKU-4001", False, INVENTORY)
b = get_stock_routed("SKU-4001", True, INVENTORY)
assert a["source"] == "local_file" and b["source"] == "mcp_server"
assert a["qty_on_hand"] == b["qty_on_hand"] == 7
print(a["source"], b["source"])
Exercise A3 · Probe semantics without a live server

Soft-fail probes must never crash the CLI. Fake an unreachable probe and a reachable one. 

def soft_probe(reachable: bool, status_code: int | None = None, error: str | None = None) -> dict:
  if reachable:
    return {"reachable": True, "status_code": status_code or 200}
  return {"reachable": False, "error": error or "connection refused"}

down = soft_probe(False)
up = soft_probe(True, 200)
assert down["reachable"] is False and "error" in down
assert up == {"reachable": True, "status_code": 200}

def require_mcp_or_raise(probe: dict) -> None:
  if not probe.get("reachable"):
    raise RuntimeError("Inventory MCP server is not reachable on port 8765.")

try:
  require_mcp_or_raise(down)
  raised = False
except RuntimeError:
  raised = True
assert raised
require_mcp_or_raise(up)
print("probe guards ok")
