AWS Bedrock sandbox learner runbook

Authenticate, confirm the sandbox identity, set the approved model target, run one curriculum verification, and clean up.

On this page 1. Sandbox limits Where commands run 2. Authenticate 3. Check identity 4. Set the target 5. Verify once 6. Clean up

1. Start with the sandbox limits

Region

us-east-1 only

Keep the console and every command in US East (N. Virginia).

Lifetime

4-hour automatic cleanup

Stop by 3 hours 30 minutes. Stopping starts cleanup, which usually blocks access for 15–20 minutes.

Do not provision resources. Use the assigned sandbox only, make one bounded inference request, and never place credentials in a file, code, chat, screenshots, or Git.

Run commands on the Ubuntu VM

Open the repository in VS Code, select Terminal → New Terminal, and run every command block below in that Ubuntu terminal:

conda activate ai_agent_env
cd /home/labuser/Desktop/Persistent_Folder/exl-ai-training-week2-claude
pwd

Use the browser only for the training sandbox portal and AWS console — never for running code.

2. Sign in, then generate your own Bedrock API key

The sandboxes are separate. Signing in to the AWS console does not authenticate the Ubuntu VM. You generate a key in the console, then move it to the VM yourself (step 4).

Current as of July 2026: Amazon Bedrock API keys (launched July 2025) are the current, simplest auth path — a single bearer-token string, not a three-part access-key/secret/session-token set.

  1. Sign in to the AWS sandbox console with the login credentials provided to you. Confirm the region selector reads US East (N. Virginia) / us-east-1.
  2. Go to Bedrock → Model catalog, find the Anthropic Claude model your trainer specifies (e.g. anthropic.claude-sonnet-4-6 — see the confirmed model list below), and confirm/request access. A one-line use case ("AI-assisted claims triage for a training exercise") is normally approved in under a minute.
  3. In the Bedrock console left navigation, select API keys.
  4. Choose the Long-term API keys tab (simplest for a multi-hour workshop; short-term keys expire with your console session) → Generate long-term API keys → set a short expiration (a few hours is plenty) → generate.
  5. Copy the key value immediately — it is shown once.
Confirmed Bedrock models in this sandbox (from the sandbox resource sheet): anthropic.claude-sonnet-4-6, anthropic.claude-haiku-4-5-20251001-v1:0, anthropic.claude-opus-4-6-v1, anthropic.claude-opus-4-7, anthropic.claude-opus-4-8. Use the exact ID your trainer specifies — do not guess a suffix.

3. Confirm you're in the right account before generating anything

Before generating the key, check the account ID / role shown in the AWS console top-right against the sandbox details shown in the training portal. If they don't match, stop and contact the sandbox administrator — do not generate a key in the wrong account.

4. Move the key to the VM, then set the model target

The AWS sandbox browser and the VM are separate machines with no shared clipboard. In the same AWS sandbox browser tab: open syncclip.in, paste the key in, note the sync code. Then, on the VM, open syncclip.in in its own browser, enter the same code, and retrieve the key.

Back in the VS Code terminal on the VM, set it via a hidden prompt — never paste it into a file:

read -rsp "Bedrock API key: " AWS_BEARER_TOKEN_BEDROCK; echo
export AWS_BEARER_TOKEN_BEDROCK
export AWS_REGION=us-east-1
export BEDROCK_MODEL_ID="<exact trainer-approved model ID>"

Boto3 and the AWS SDKs read AWS_BEARER_TOKEN_BEDROCK automatically when constructing a Bedrock client — no separate config file, no aws configure step.

5. Run one curriculum verification

From the repo root on the VM, run the reference script once. It pins us-east-1, makes exactly one Converse request, and applies a deterministic (non-model) authorization gate.

uv run python W2D2/snippets/bedrock_claim_classifier.py CLM-424063

Success prints the claim, the model's one-word urgency classification, and the authorization decision. Do not loop this call. Review the reference script and the full Day 2 PM walkthrough rather than writing a separate smoke-test program.

Need command details? Run aws help or aws bedrock help in the Ubuntu terminal. For identity, access, model availability, or permission issues, use the sandbox administrator/support contact in the training portal.

6. Unset, log out, and stop

unset AWS_BEARER_TOKEN_BEDROCK AWS_REGION BEDROCK_MODEL_ID
  1. Clear the syncclip.in note you used to move the key.
  2. Close the terminal and log out of the AWS console.
  3. If you generated a long-term key, don't reuse it in a later session — let it expire or revoke it in the Bedrock console.
  4. Choose Stop Sandbox in the training portal and confirm.
  5. Do not restart the sandbox to watch cleanup.
