Understanding context, and manual compaction

Everything Claude Code "knows" right now is exactly what's in its context window — nothing more, nothing magic.

Concept: Context Windows and Compaction

The Big Picture

Claude Code has a context window — a finite bucket of tokens that holds everything Claude is currently aware of:

  • Your system prompt (the instructions you're reading right now, roughly)
  • All your CLAUDE.md files (user, project, subdirectory)
  • Every message you've sent
  • Every tool call result
  • Your custom commands, skills, subagent specs

This bucket has a limit (usually very large — 200k+ tokens for recent models). When a session runs long and the context gets full, Claude Code automatically compresses older turns into a summary, making room for new work. This process is called compaction, and it's lossy — some detail gets dropped to fit the summary.

What Gets Lost in Compaction

When Claude Code compacts context:

  • Conversational detail is summarized. You discussed "let me trace through the recursive function," and Claude spent 5 turns analyzing it. Compaction might reduce that to "we discussed recursion depth" — gist preserved, detail lost.
  • Tool results older than a few turns get summarized. You read 10 files; compaction might reduce that to "we reviewed multiple files." The exact contents might be forgotten unless they're important to the summary.
  • Reasoning and intermediate thoughts disappear. When Claude worked through a problem step-by-step, those intermediate steps vanish. Only the conclusion survives.

What Survives Compaction (Always)

Artifacts and disk state always survive:

  • CLAUDE.md files — Re-read fresh at the start of any session. They don't depend on being carried in conversational memory.
  • Written files — A Python script you edited is on disk. Compaction doesn't touch it. A new session reads it fresh.
  • Git history — Commits are permanent. Compaction never affects them.
  • Custom commands, skills, subagents you defined — Stored on disk in .claude/, not in memory. (One nuance: the one-line skill index Claude sees at startup is not automatically re-added after compaction — only skills actually invoked during the conversation get re-injected. The skill files themselves are never touched; invoking one again brings it right back.)

Key insight: If you want something to survive compaction reliably, write it to disk (CLAUDE.md, a file, git). Don't rely solely on "we discussed this 20 turns ago."

Manual Compaction (/compact)

You can trigger compaction yourself:

/compact

When to use it: After finishing a big, noisy sub-task (like debugging, reading 50 files, running a test suite), compacting clears the noise while it's still fresh. Rather than waiting for automatic compaction to happen unpredictably later, you control when the loss occurs.

What happens: Claude summarizes the current conversation, clears the old detail, and starts fresh with the summary. The rest of your session continues, but with reduced context.

Compaction Lifecycle Diagram

Session starts (context empty)
    ↓
Turns accumulate (context fills)
    ↓
Context approaches limit (automatic compaction triggers, OR you run /compact)
    ↓
Compaction summarizes older turns
    ↓
Detail is lost, summary is kept
    ↓
Session continues with more room, but less historical detail
    ↓
If you need that detail again, it's gone—reread files from disk

Context Window Sizes

Claude Code's context window is 200,000 tokens by default — the same for every model (Haiku, Sonnet, or Opus). This is a Claude-Code-level limit, not a raw per-model ceiling:

  • Default, any model: 200k tokens (roughly 150k words)
  • Extended context (opt-in): Opus (4.6 and later) and Sonnet 4.6 can switch to a 1-million-token window for long sessions with large codebases — select it with /model opus[1m] or /model sonnet[1m] (included automatically on some subscription plans, or via usage credits on others).
  • Newest models (e.g. Sonnet 5, Fable 5): run at the 1M-token window by default on the Anthropic API — no [1m] suffix needed.

For most projects, 200k is enormous — you'd have to read thousands of files or have extremely long conversations to hit it naturally. (Correction: an earlier draft of this page referenced a "Claude 5 (coming)" model with "even larger" context — no such model exists. The real mechanism for a bigger window is the 1M-token extended context option above, already available today on qualifying models/plans.)

Real-World Use Cases

1. Long Debugging Sessions

The problem: You're debugging a complex issue. You read 30 files, run 20 test cases, trace through the code step-by-step. Your context is now full of debugging noise — tool results, intermediate reasoning, failed attempts.

The solution: When you finally find and fix the bug, immediately run /compact. This clears the debugging noise while you're fresh on the solution.

The result: Your context is fresh for the next task. If you need to reference the bug fix again, it's in git; you don't need it in memory.

2. Large Codebase Exploration

The problem: You're exploring an unfamiliar codebase. You ask Claude to find all API endpoints, trace through a workflow, read 50 files to understand the architecture. Context fills fast.

The solution: Once you have the insights you need, compaction clears the file-reading noise. Write your findings (architecture diagram, notes) to CLAUDE.md or a file, then compact.

The result: You keep the insights (written to disk), lose the noise (tool results, intermediate steps). Clean context for the next task.

3. Test Suite Runs

The problem: You run 200 test cases to validate your changes. The output fills context with pass/fail results, logs, and traces.

The solution: After reviewing test results and fixing issues, run /compact to clear the test logs.

The result: The test passes remain in git; context is clean for development.

4. Documentation Reviews

The problem: You review 20 documentation files, each 10k words, looking for outdated content. Context is consumed by file contents that are now no longer relevant.

The solution: Document your findings (which files need updating), then compact to clear the file contents.

The result: You keep your actionable findings, lose the raw docs (still available on disk if needed). Clean context.

5. Multi-Step Refactoring with Exploratory Sub-Tasks

The problem: You're refactoring a module. Step 1 involves exploring the current code (noisy). Step 2 is making the actual changes (needs clarity). After step 1, context is full of exploration noise.

The solution: After exploring, document your refactoring plan in CLAUDE.md, then run /compact before starting step 2.

The result: Step 2 starts fresh. Your plan (in CLAUDE.md) survives; exploration noise doesn't.

Hands-on Practice: Five Examples

Example 1: Check Your Current Context Status

Claude Code chat panel

Step 1: Ask Claude about context usage:

Prompt
How much of your context window are you currently using? Give me an estimate
as a percentage, and tell me what the main components are (system prompt,
CLAUDE.md, conversation history, etc.).

What you'll see: Claude gives you an estimate of context usage. Early in a session, it's typically 5-10%. After many turns or large file reads, it might be 40-60%.

Checkpoint You now have a baseline for your current context usage.

Example 2: Deliberately Fill Context, Then Compact

Claude Code chat panel

Step 1: Ask Claude to read many files (to generate noise):

Prompt
Read every .html file in W2D0/ and give me a one-line summary of what each
one teaches. Don't overthink it—just a quick summary of the topic.

What happens: Claude reads all the W2D0 HTML files. Your context is now filled with file contents and summaries.

Step 2: Check context usage again:

Prompt
Check your context usage now. How much has it grown from your earlier estimate?

What you'll see: Context usage has noticeably increased—maybe from 10% to 40% or higher, depending on file sizes.

Step 3: Now trigger manual compaction:

/compact

What happens: Claude summarizes the conversation and clears old detail.

Step 4: Check context usage after compaction:

Prompt
Check your context usage now. How much has it shrunk after compaction?

What you'll see: Context is significantly reduced. The detailed file contents are gone; only a summary remains.

Checkpoint You've seen context fill up and compaction shrink it. This is the real trade-off.

Example 3: Prove Context Loss After Compaction

Claude Code chat panel

Setup: You just compacted. Now ask Claude to recall detailed information from before compaction.

Step 1: Ask for detailed recall:

Prompt
Recall the exact content of the CLAUDE.md file we read earlier. Quote
the first 3 bullet points word-for-word.

What should happen: Claude can't recall exact text. It might say "I don't have that detail anymore" or give you a paraphrase. This is compaction at work—detail is lost.

Step 2: Prove files are still on disk:

Prompt
Now read CLAUDE.md fresh from disk and give me the actual first 3 bullet points.

What should happen: Claude reads the file fresh and gives you exact text. The file survived compaction because it's on disk, not in memory.

Checkpoint You've proven that conversational detail is lost, but disk artifacts survive.

Example 4: Write Important Details to CLAUDE.md Before Compacting

Claude Code chat panel

Setup: You want to preserve important findings across compaction.

Step 1: Ask Claude to add a section to CLAUDE.md with your findings:

Prompt
Add a new section to CLAUDE.md called "## W2D0 Context Management Learnings"
and list 3 key takeaways from our discussion about context compaction and
what survives.

Step 2: Verify the addition:

# On Mac/Linux
tail -20 CLAUDE.md

# On Windows (PowerShell)
Get-Content CLAUDE.md | Select-Object -Last 20

Step 3: Now run compaction:

/compact

Step 4: Verify that your added section is still there:

# On Mac/Linux
grep -A 5 "W2D0 Context Management" CLAUDE.md

# On Windows (PowerShell)
Select-String "W2D0 Context Management" CLAUDE.md -Context 0,5

What should happen: Your addition is still there. CLAUDE.md always survives compaction because it's on disk and gets re-read fresh.

Checkpoint You've proven that disk artifacts survive compaction reliably.

Example 5: Simulate a New Session to Confirm Persistence

Claude Code chat panel

Setup: A real proof that your additions to CLAUDE.md aren't just in memory—they'd survive a new session entirely.

Step 1: Ask Claude to imagine a completely new session:

Prompt
Imagine you're a brand-new Claude Code session starting from scratch in
this repo (you have zero memory of our conversation). You load CLAUDE.md.
Do you see the "W2D0 Context Management Learnings" section we added? What does it say?

What should happen: Claude reads CLAUDE.md fresh and sees the section we added. It's not a memory of our conversation—it's a real file on disk.

Checkpoint You've proven that anything written to disk survives compaction and even session boundaries. It's durable.

Key insight: This is why CLAUDE.md is powerful. It's not just a conversation artifact—it's a durable, persistent knowledge base that survives compaction and session boundaries.
