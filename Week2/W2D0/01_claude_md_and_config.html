CLAUDE.md & the .claude folder — hierarchical discovery

You've already been using CLAUDE.md all through Week 2 without necessarily knowing how Claude Code finds it, or that it isn't the only one that can exist.

00 Orientation 01 CLAUDE.md 02 Settings/modes 03 Slash commands

Concept

What it is. CLAUDE.md is project memory — plain markdown, read at the start of every session. It's not the only scope: a user-scoped ~/.claude/CLAUDE.md applies to every project you open, and nested project subdirectories can carry their own, more specific CLAUDE.md too.

  • They combine, they don't override. User-level, project-root, and subdirectory CLAUDE.md files all load together when relevant — think of it as layered context that gets more specific as you go deeper, not a single winner-takes-all file.
  • The .claude folder is the sibling for everything else. Settings, custom commands, subagent definitions, and hooks configuration all live under a project's .claude/ directory (or the user-level ~/.claude/) — CLAUDE.md is just the plain-text memory piece.
  • Why this matters practically. A user-level CLAUDE.md is the right place for "always write commit messages this way" (true across every project you touch). A project-level one is for "this specific repo's conventions" — which is what you've been extending all week.
