Capstone Stage 1 — Setup & EDA

Thirteen topics in, you've used Claude Code to build, test, and guard small pieces of software. Now you point it at a real dataset and direct it to build the first stage of a five-stage ML project end to end: load the data, characterize it, and hand off a clean file the next stage can trust.

Concept

Exploratory data analysis is the step every rushed ML project skips and every reliable one doesn't. Before a model sees a single row, you need to know what you're actually feeding it.

  • Missing values break training silently. A model doesn't usually crash on a NaN — it either errors deep inside a library call with a confusing stack trace, or worse, it trains anyway with imputed garbage and you don't find out until predictions look wrong. Checking isna().sum() up front turns a mystery debugging session later into a one-line fact now.
  • Correlations tell you what the model is likely to lean on. If one feature is strongly related to the target before you've trained anything, that's a preview of what a linear model will weight heavily — and a sanity check for later: if your trained model ends up ignoring a feature that looked highly correlated here, that's worth asking why.
  • Geography is an unusual dimension for tabular EDA, and this dataset has it. Most tabular datasets give you a correlation matrix and you're done. Latitude and longitude aren't just two more numeric columns — they encode location, and location in California housing data captures things no single column does on its own (coastal proximity, metro-area effects). A correlation heatmap will underrate them; a map will not. That's a real reason to build both plots, not just one.
  • This stage is a contract with Stage 2, not a one-off report. Whatever this script outputs — a saved dataframe with clean types and no missing values — is exactly what the model-training script in Stage 2 will read and trust. Sloppy EDA here becomes a debugging problem there.
