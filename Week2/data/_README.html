Day 3 canonical data and generated stores

Day 3 reads the six shipped policy Markdown files, shipped insurance/policy_chunks.json, insurance/rag_goldens.json, supply/supplier_kg.json, customer threads, and logistics delay events. The chunk JSON is source-controlled input, not a generated vector index. Pinecone indexes/namespaces, PostgreSQL/pgvector tables and indexes, Chroma persistence, SQLite checkpoints/event receipts, and DiskCache directories are generated runtime state.

Pinecone is the primary implemented and runtime-tested classroom vector path. PostgreSQL with pgvector and Chroma are fully implemented alternatives whose runtime verification is intentionally deferred. Follow W2D3AM/_VECTOR_STORES_SETUP.html; detailed pgvector provisioning and validation maps to d3amt2c03_pgvector_store.py.

Home policy identity: POL-HOME-010 is the parent homeowners policy represented by the water and flood-rider source files. POL-HOME-FLOOD is the rider expectation used by relevant retrieval/evaluation checks; do not rewrite the parent policy ID as the rider ID.

The rebuilt 34-script path requires Anthropic API, SentenceTransformers, Pinecone, LangGraph, NetworkX, CrossEncoder reranking, Pydantic, SQLite checkpoints/events, FastAPI webhook handling, DiskCache, and typed citations. LlamaIndex is not used by these teaching scripts; they use native clients and LangGraph.

Day 1 generated evidence

Day 1 never mutates authoritative CSV, SQLite, or JSONL fixtures. Configured Day 1 runs write reconstructable evidence under W2D1/outputs/day1/, including am_handoff.json, triage_decision.json, agent_trace.jsonl, sdk_session.json, usage_summary.json, and hold_release_ledger.jsonl. The hold-release ledger records learner-approved commands and provides process-restart idempotency; it is generated output, not shipment source data.

Day 2 canonical data and providers

Day 2 AM reads insurance/workflow_cases_15.json for all 15 underwriting cases. Day 2 PM reads insurance/claim_narratives_10.json for claim-agent work and supply/inventory.json for MCP/A2A protocol work. The CrewAI primer also reads insurance/fnol_emails.csv and generated insurance/claims.db; the Google ADK primer reads inventory plus both logistics JSONL files; the Microsoft Agent Framework primer reads banking/customer_threads.json plus the two generated banking Parquet files.

  • Anthropic: required for the CrewAI primer and the API-backed Day 2 Anthropic, LangGraph, and Claude Agent SDK chains.
  • Gemini API: required by the Google ADK primer through GOOGLE_API_KEY and GOOGLE_ADK_MODEL.
  • Microsoft Foundry: required by the Agent Framework primer through Azure CLI authentication, FOUNDRY_PROJECT_ENDPOINT, and FOUNDRY_MODEL.

All domain reads must retain exact source IDs. Unknown records, denied access, provider failures, and unavailable protocol endpoints are explicit outcomes; no primer or script may invent a fallback record.

Day 2 MCP and A2A localhost setup

From the Week2 root, keep the selected server running in one terminal and use a second terminal for its client:

uv run python W2D2\W2D2PM\d2pmt2c01_mcp_server.py --self-test
uv run python W2D2\W2D2PM\d2pmt2c01_mcp_server.py
uv run python W2D2\W2D2PM\d2pmt2c02_mcp_client.py --sku SKU-1002

uv run python W2D2\W2D2PM\d2pmt3c01_agent_card_validate.py
uv run python W2D2\W2D2PM\d2pmt3c03_inventory_a2a_server.py
uv run python W2D2\W2D2PM\d2pmt3c02_a2a_task.py --sku SKU-1002

uv run python W2D2\W2D2PM\d2pmt6c03_claim_mcp_server.py
uv run python W2D2\W2D2PM\d2pmt6c03_claim_a2a_server.py
uv run python W2D2\W2D2PM\d2pmt6c03_protocol_workflow.py --thread-id protocol-demo

MCP uses official Streamable HTTP at http://127.0.0.1:8765/mcp and exposes get_stock, list_low_stock, and inventory://canonical/snapshot; it exposes no write tool. A2A serves the retained agent_card.json and JSON-RPC endpoint on http://127.0.0.1:9999, returning working/completed/failed task states and a canonical inventory artifact.

Topic 6 c03 uses supplied claim-specific services backed by insurance/claim_narratives_10.json: MCP Streamable HTTP at http://127.0.0.1:8000/mcp exposes the read-only get_claim tool, while A2A at http://127.0.0.1:9999 advertises claim_operator_review. The A2A input requires the exact canonical claim and narrative IDs, learner_approved: true, and an 8-128 character idempotency key. Stop the inventory A2A server before starting the claim A2A server because both default to port 9999. The workflow has no local fallback when either protocol endpoint is unavailable.
