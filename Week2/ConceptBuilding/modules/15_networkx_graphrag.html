Why GraphRAG (and when not)

Flat vector RAG answers “what documents are similar to this question?” GraphRAG answers “how are these entities related across one or more hops?” In supply-chain ops that difference matters: a learner asking “Which warehouse sits between EuroParts and the hydraulic pump?” needs edges, not just chunk similarity.

Layer Job Tool in this lab
Vector index Find candidate entities / docs by meaning Pinecone / SentenceTransformers (primary); Chroma alternative in module 12
Knowledge graph Traverse typed relations for multi-hop context NetworkX DiGraph (this module)
Answer assembly Merge vector hits + path facts into grounded text Your agent / notebook glue
Cost note (~3–5×) GraphRAG is typically about 3–5× more expensive than flat vector RAG: more retrieval steps, more tokens of path context, and often an extra LLM call to decide which entities to expand. Use it when relationships matter (supplier → warehouse → SKU). Skip it for FAQ-style single-hop questions.
Why NetworkX, not Neo4j? Day 3 implements the graph path at classroom depth. An in-memory nx.DiGraph loads from JSON in milliseconds, needs no Aura credentials, and exposes the same mental model (nodes, typed edges, shortest path, predecessors / successors). Production teams may later swap the store for Neo4j / Neptune — the traversal ideas stay the same.

Beginner — DiGraph, nodes, relation edges Beginner

Goal: load JSON into a directed graph and prove that edge attributes (especially relation) survive the load. NetworkX June 2026 API used here is stable: nx.DiGraph, add_node, add_edge, attribute access via G.nodes[id] and G[u][v]["relation"].

1. Import and load the fixture

import json
from pathlib import Path
import networkx as nx

# Working dir: Week2/ConceptBuilding
kg_path = Path("data/supplier_kg.json")
payload = json.loads(kg_path.read_text(encoding="utf-8"))

print(payload.keys())          # dict_keys(['nodes', 'edges'])
print(len(payload["nodes"]))   # 6
print(len(payload["edges"]))   # 5

2. Build a DiGraph (direction matters)

Use DiGraph, not undirected Graph. Supply edges point supplier → SKU / warehouse; reversing them would invent false facts. 

G = nx.DiGraph()

for node in payload["nodes"]:
    # id is the graph key; remaining fields become node attributes
    G.add_node(node["id"], **{k: v for k, v in node.items() if k != "id"})

for edge in payload["edges"]:
    G.add_edge(
        edge["source"],
        edge["target"],
        relation=edge["relation"],
    )

print("nodes", G.number_of_nodes())   # 6
print("edges", G.number_of_edges())   # 5
print("is_directed", G.is_directed()) # True

3. Inspect node and edge attributes

# Node attributes
print(G.nodes["SUP-002"])
# {'type': 'supplier', 'name': 'EuroParts GmbH', 'region': 'EU'}

# Edge attribute: the relation string
print(G["SUP-002"]["SKU-2044"]["relation"])  # supplies
print(G["SUP-003"]["SKU-1002"]["relation"])  # backup_supplier_for

# List every typed edge
for u, v, data in G.edges(data=True):
    print(f"{u} -[{data['relation']}]-> {v}")
Operator tip Always store business meaning on the edge (relation=...). Counting neighbors without filtering by relation will mix primary suppliers with backup suppliers and confuse the answer.

Goal: answer multi-hop questions with predecessors, successors, and nx.shortest_path. These three calls are the core of W2D3/W2D3AM/d3amt3c01_networkx_traversal.py. The next steps add SentenceTransformer vector-seeded expansion and an Anthropic API cited answer.

4. Predecessors and successors

In a DiGraph, direction is absolute:

  • G.predecessors(n) — nodes with an edge into n
  • G.successors(n) — nodes with an edge out of n
# Who points at the hydraulic pump?
list(G.predecessors("SKU-2044"))
# ['SUP-002', 'WH-EU-01']

# What does EuroParts point at?
list(G.successors("SUP-002"))
# ['SKU-2044', 'WH-EU-01']

# Filter predecessors that are suppliers
suppliers_for_sku = [
    n for n in G.predecessors("SKU-2044")
    if G.nodes[n].get("type") == "supplier"
]
print(suppliers_for_sku)  # ['SUP-002']

5. Relation-aware neighbor queries

def neighbors_with_relation(G, node, relation, direction="out"):
    """Return neighbor ids connected by a specific relation string."""
    if direction == "out":
        return [
            v for _, v, data in G.out_edges(node, data=True)
            if data.get("relation") == relation
        ]
    return [
        u for u, _, data in G.in_edges(node, data=True)
        if data.get("relation") == relation
    ]

print(neighbors_with_relation(G, "SKU-1002", "backup_supplier_for", "in"))
# ['SUP-003']

print(neighbors_with_relation(G, "SUP-002", "ships_via", "out"))
# ['WH-EU-01']

6. Shortest path between entities

nx.shortest_path(G, source, target) returns a list of node ids along the fewest hops (unweighted). Catch nx.NetworkXNoPath when no directed path exists. 

# EuroParts → Frankfurt Hub is a single ships_via hop
nx.shortest_path(G, "SUP-002", "WH-EU-01")
# ['SUP-002', 'WH-EU-01']

# EuroParts can also reach the SKU via the warehouse:
# SUP-002 → WH-EU-01 → SKU-2044
nx.shortest_path(G, "SUP-002", "SKU-2044")
# ['SUP-002', 'SKU-2044']   # direct supplies edge is shorter

# No path the other way (DiGraph!)
try:
    nx.shortest_path(G, "SKU-2044", "SUP-002")
except nx.NetworkXNoPath:
    print("no reverse path — direction encodes business fact")

7. Classroom multi-hop query (SKU-2044)

Pattern used in the day-3 demo: find suppliers, backup suppliers, warehouses reachable from those suppliers, then sample shortest paths. 

sku = "SKU-2044"

suppliers = [
    n for n in G.predecessors(sku)
    if G.nodes[n].get("type") == "supplier"
]

backup = [
    n for n in G.nodes
    if G.nodes[n].get("type") == "supplier"
    and G.has_edge(n, sku)
    and G[n][sku].get("relation") == "backup_supplier_for"
]

warehouses = []
for supplier in suppliers:
    for wh in G.successors(supplier):
        if G.nodes[wh].get("type") == "warehouse":
            warehouses.append(wh)

paths = []
for supplier in suppliers:
    for wh in warehouses:
        try:
            paths.append(nx.shortest_path(G, supplier, wh))
        except nx.NetworkXNoPath:
            pass

print("suppliers", suppliers)     # ['SUP-002']
print("backup", backup)           # [] for SKU-2044
print("warehouses", warehouses)   # ['WH-EU-01']
print("paths", paths)             # [['SUP-002', 'WH-EU-01']]

8. Conceptual hybrid pipeline

┌─────────────────┐     ┌──────────────────┐
│ Vector search   │     │ Graph traversal  │
│ (similarity)    │     │ (typed hops)     │
└────────┬────────┘     └────────┬─────────┘
         │                       │
         └──────────┬────────────┘
                    ▼
           Combined grounded answer
           (entities + path facts + citations)
  1. Entity seed — vector (or keyword) hit names a SKU / supplier id.
  2. Expand — predecessors / successors / shortest_path pull related nodes.
  3. Filter — keep only edges whose relation is allowed for this question.
  4. Assemble — pass path strings + node attrs into the LLM context (or a deterministic template for the lab).

9. Simulate vector hits, then expand

# Pretend a retriever returned these chunk hits (ids extracted by NER / metadata)
vector_hits = [
    {"chunk_id": "doc-77", "score": 0.81, "entity_id": "SKU-2044"},
    {"chunk_id": "doc-12", "score": 0.74, "entity_id": "SUP-002"},
]

def expand_entity(G, entity_id, max_hops=2):
    """Collect 1-hop context; optionally sample shortest paths to related warehouses."""
    if entity_id not in G:
        return {"entity": entity_id, "error": "not_in_kg"}

    node = dict(G.nodes[entity_id])
    preds = list(G.predecessors(entity_id))
    succs = list(G.successors(entity_id))
    edges_out = [
        {"to": v, "relation": d["relation"]}
        for _, v, d in G.out_edges(entity_id, data=True)
    ]
    edges_in = [
        {"from": u, "relation": d["relation"]}
        for u, _, d in G.in_edges(entity_id, data=True)
    ]

    path_snippets = []
    if node.get("type") == "sku":
        for pred in preds:
            if G.nodes[pred].get("type") == "supplier":
                for wh in G.successors(pred):
                    if G.nodes[wh].get("type") == "warehouse":
                        try:
                            path_snippets.append(nx.shortest_path(G, pred, wh))
                        except nx.NetworkXNoPath:
                            continue

    return {
        "entity": entity_id,
        "node": node,
        "predecessors": preds,
        "successors": succs,
        "edges_in": edges_in,
        "edges_out": edges_out,
        "path_snippets": path_snippets[:max_hops],
    }

expansions = [expand_entity(G, hit["entity_id"]) for hit in vector_hits]
for row in expansions:
    print(row["entity"], "→ paths", row["path_snippets"])

10. Deterministic answer template (no LLM required)

def graphrag_answer(G, sku: str) -> dict:
    """Traverse supplier → warehouse context for a SKU (concept depth)."""
    if sku not in G:
        raise ValueError(f"SKU not found in KG: {sku}")

    suppliers = [
        n for n in G.predecessors(sku)
        if G.nodes[n].get("type") == "supplier"
    ]
    backup = [
        n for n in G.nodes
        if G.nodes[n].get("type") == "supplier"
        and G.has_edge(n, sku)
        and G[n][sku].get("relation") == "backup_supplier_for"
    ]
    warehouses = []
    for supplier in suppliers:
        for wh in G.successors(supplier):
            if G.nodes[wh].get("type") == "warehouse":
                warehouses.append(wh)

    path_examples = []
    for supplier in suppliers[:2]:
        for wh in warehouses[:2]:
            try:
                path_examples.append(nx.shortest_path(G, supplier, wh))
            except nx.NetworkXNoPath:
                continue

    return {
        "sku": sku,
        "suppliers": [G.nodes[n] for n in suppliers],
        "backup_suppliers": [G.nodes[n] for n in backup],
        "warehouses": [G.nodes[n] for n in warehouses],
        "paths": path_examples,
        "lesson": (
            "Graph traversal adds relationship context; "
            "use when hops matter (~3-5x cost)."
        ),
    }

result = graphrag_answer(G, "SKU-2044")
print(result["suppliers"])
print(result["warehouses"])
print(result["paths"])
print(result["lesson"])

11. When GraphRAG is worth the 3–5× cost

Question shapeFlat vector RAG?GraphRAG?
“What does the brake-pad policy say about returns?” Yes — single doc hop Overkill
“Who supplies SKU-2044 and via which warehouse?” Fragile / incomplete Justified
“List backup suppliers if NorthStar fails for SKU-1002” May miss typed relation Justified
“Summarize last week’s delay emails” Yes No graph needed
Do not invent graph facts If a path does not exist in NetworkX, say so. Never fabricate a ships_via or backup_supplier_for edge to satisfy the prompt. Same rule as claim / loan / shipment tools: use domain data only.
