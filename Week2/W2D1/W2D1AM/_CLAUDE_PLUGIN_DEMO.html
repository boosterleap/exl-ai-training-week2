Purpose

Mirror AM notebook outcomes live in Claude Code: agentic loop, reasoning patterns, tool contracts, memory/handoff, fail-closed grounding (CLN-001 vs CLN-007), and application-owned budgets — without running LangGraph/API cells.
Important: Opening _DEMONSTRATIONS.ipynb and executing live LLM cells still needs an API key. This HTML path is the plugin-only classroom demo. Keep the notebook open as a visual map; run the prompts below in the Claude panel.

  • Companion notebook: _DEMONSTRATIONS.ipynb.

What you need to access / set

Accounts & install (once per VM / machine)

  1. Claude account with Claude Code / VS Code Claude extension access (Pro/Team/Enterprise subscription that includes Claude Code). No Console API key required for this guide.
  2. VS Code (or Cursor) on the Ubuntu learner VM with the Claude / Claude Code extension installed.
  3. Repo on disk under the persistent folder (typical VM layout): 
    /home/labuser/Persistent_Folder/.../EXL-CampusHire/Week2
  4. Python venv only needed if you also open notebooks later; plugin demo uses Claude’s tools (Read / Bash / sqlite). Typical: /home/labuser/venv or course Week2/.venv.

How to set Claude plugin access

  1. Open VS Code → Extensions → confirm Claude / Claude Code is installed and enabled.
  2. Open the Claude panel (activity bar Claude icon, or Command Palette → “Claude: Open”).
  3. Sign in with the classroom Claude account when prompted. Complete browser OAuth if shown.
  4. Confirm the status shows signed-in / ready (not “API key missing”). Plugin auth ≠ ANTHROPIC_API_KEY.
  5. Do not paste API keys into chat, .env, or shared screens during this demo.

Workspace settings that must be true before demos

  1. Open folder = W2D1AM (File → Open Folder), not the whole monorepo root if that prevents project rules from loading. If you must open Week2, say in the first prompt: “Use rules from W2D1/W2D1AM/CLAUDE.md.”
  2. Trust the workspace when VS Code asks (required for project hooks/skills).
  3. Allow Claude to use Read and limited Bash (sqlite/python) when permission prompts appear — project .claude/settings.json already allowlists teaching commands.
  4. Writes should stay under Week2/W2D1/outputs/day1/. Decline writes that invent claim/policy IDs.

Chronological live demo (follow in order)

Keep _DEMONSTRATIONS.ipynb scrolled to the matching section title while you paste each prompt.

  1. §00 — Warm-up: rules on screen

    Show: open CLAUDE.md briefly. Say: “Claude Code loads project rules automatically.”

    Summarize CLAUDE.md in 5 bullets for operators.
Emphasize: never invent FNOL/claim/policy IDs; fail closed when evidence is incomplete.

    Expected: concise rules; mention fixtures and fail-closed.

  2. §01 — Agentic loop (observe → decide → act)

    Notebook map: agentic loop / hybrid routing for CLN-001.

    Slash (preferred): type /day1-am-loop then Enter.

    Or paste:

    /day1-am-loop

If slash skills are unavailable, follow the skill manually:
Read fnol_emails.csv for CLN-001, extract claim/policy IDs from the row only,
look up claim/policy in claims.db if needed, explain observe→decide→act→observe
in 4 bullets, then return TriageDecision JSON with stop_reason completed.
Never invent IDs.

    Expected on screen:

    • CLN-001 → claim CLM-424063, policy POL-787532354, route toward fnol_intake
    • 4-bullet loop explanation
    • Valid TriageDecision-shaped JSON

  3. §02 — Reasoning patterns (plan / reflect / compare)

    Using ONLY the FNOL row for CLN-001 from fixtures (do not invent):
1) Write a 3-step evidence-first plan (fnol → claim → policy).
2) Draft a TriageDecision JSON.
3) Critique the draft: list any field that is not backed by the FNOL row alone.
4) Compare two routes: fnol_intake vs escalate_adjuster — pick one with a one-sentence reason.
Keep the answer operator-facing and short.

    Expected: plan mentions real IDs from FNOL; critique notes claim/policy details need tools/DB; preferred route usually fnol_intake.

  4. §03 — Tool contracts & grounding

    Teach typed tool contracts without inventing data:
1) Propose a Pydantic-like schema for fnol_lookup with email_id pattern ^CLN-\d{3}$.
2) Read fixtures and collect evidence for CLN-001 (FNOL + claim + policy if present).
3) Produce a grounded TriageDecision where case_id is the real CLM- id from evidence.
4) Then collect evidence for CLN-007. If incomplete, refuse with status=refused and refusal_reason.
Return JSON: {"CLN-001": {...}, "CLN-007": {...}}.

    Or slash: /day1-am-grounding

    Expected: CLN-001 completed with CLM-424063; CLN-007 refused / fail-closed; no invented claim id.

  5. §04 — Memory / handoff summary

    Investigate CLN-001 from fixtures only.
Return:
1) a short working_summary (1–2 sentences) an operator can resume from
2) a TriageDecision JSON
3) list of evidence sources you actually read
Do not claim you wrote to production systems.

    Expected: working summary mentions FNOL + claim + policy and fnol_intake.

  6. §05–§06 — Fail-closed + application-owned budget

    Slash: /day1-am-budget

    /day1-am-budget

Narrate an application-owned loop that must call fnol→claim→policy for CLN-001.
Show budget_1 (max_model_calls=1) stopping with model_call_budget_exhausted
vs budget_3 allowing more progress. Return {"budget_1":..., "budget_3":...}.
Teach: the application owns stop_reason, not the model.

    Expected: contrasting stop reasons; pedagogy that budgets are application-owned.

  7. Optional — specialist subagent

    Use the fnol-specialist agent (or follow .claude/agents/fnol-specialist.md).
Look up CLN-001 only from insurance fixtures and return a 5-line operator brief.
If evidence is missing, refuse.

    Expected: brief grounded on Jennifer Garcia / fence damage / high urgency / fnol_intake.

  8. Optional — persist teaching handoff (write gate)

    Write a teaching handoff JSON for CLN-001 to
Week2/W2D1/outputs/day1/am_plugin_handoff_CLN-001.json
Include: case_id, route_queue, working_summary, idempotency_key (use am-plugin-cln001-001),
and sources_read. Do not invent fields. If write is blocked, show the refusal reason.

    Expected: file created under outputs, or a clear gate message from the Write/Edit hook.

    Say aloud: “Hooks remind us writes are gated — same idea as learner approval + idempotency in PM.”

Troubleshoot / talking points

  • “Where is the API key?” — Not used here. Plugin uses Claude login. Notebooks still need keys if executed for real.
  • Claude invents CLM ids for CLN-007 — stop; re-run /day1-am-grounding; point at CLAUDE.md.
  • Wrong folder — skills/hooks missing; reopen W2D1AM.
  • sqlite blocked — allow Bash for sqlite3 / python once; settings already allowlist teaching patterns.
  • Timebox — if short on time: Steps 1 → 2 → 4 (loop + grounding) cover the AM thesis.
