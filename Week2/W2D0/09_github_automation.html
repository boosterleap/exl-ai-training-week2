GitHub operations automation

Claude Code drives the gh CLI directly — reading, triaging, and (with your approval) creating issues, PRs, and reviews.

Concept: GitHub Operations Through gh CLI

The Big Picture

GitHub automation in Claude Code is straightforward: gh (the official GitHub CLI) is just another command Claude can run. If you're logged in with gh auth login, Claude Code can read PRs, list issues, create issues, comment, run reviews — all through Bash calls.

No special integration needed for this workflow. It's the same Bash tool you use for anything else — as long as you're logged in via gh auth login, Claude just runs gh commands like any other shell command.

Note — a separate, dedicated integration also exists. Anthropic ships an official GitHub App/Action (anthropics/claude-code-action, installed with /install-github-app from the Claude Code terminal) that lets Claude respond to @claude mentions directly on GitHub issues/PRs and run as a CI job. That's a different mode from what this page covers — it's for triggering Claude *from* GitHub events, not for driving gh interactively from your terminal session. For the read/write patterns below (an active Claude Code session calling gh via Bash), the "no special integration" framing holds.

Read vs. Write Operations

Read operations (safe to explore):

  • List issues/PRs with filters
  • View a PR diff and code review
  • Check CI status and test results
  • Read issue comments and discussions

Write operations (visible to your team, require approval):

  • Create an issue or PR
  • Add a comment to an existing issue/PR
  • Approve a PR or request changes
  • Merge a PR
  • Close/open issues

Key point: Write operations are public and permanent. Before Claude runs gh issue create or gh pr create, always: 1. Have it draft the content (title, body, description) 2. Review it carefully 3. Explicitly approve before it posts

Common gh Commands

Command What It Does
gh auth status Check if you're logged in
gh issue list List all open issues
gh issue list --search "label:bug" List issues with a specific label
gh issue create --title "T" --body "B" Create a new issue
gh pr list List all open pull requests
gh pr view 42 View PR #42 details
gh pr diff 42 View the code changes in PR #42
gh pr review 42 --comment -b "feedback" Comment on PR #42

Real-World Use Cases

1. Automated Issue Triage

The problem: Your repo gets 50 new issues per week. Many are duplicates, outdated, or missing details. Manual triage takes hours.

The solution: Claude Code reads all open issues, identifies duplicates, checks if they're stale (no updates in 6 months), and adds labels/comments suggesting closure or requesting more info.

The result: Issues are pre-triaged. Your team spends time on real work, not administrative sorting.

2. Automated Code Review

The problem: Every PR needs a review before merging. Review checklists are long and tedious (style, security, tests, documentation).

The solution: Claude Code reads the PR diff and automatically checks against your review checklist. It leaves detailed comments on the PR with findings.

The result: First-pass code review is automated. Maintainers focus on logic and architecture, not style.

3. Release Notes Generation

The problem: Time to cut a release. You manually grep through commit messages and PRs to write release notes.

The solution: Claude Code lists all PRs merged since the last tag, extracts titles/descriptions, and generates organized release notes grouped by feature/bugfix/breaking change.

The result: Release notes are ready in minutes, not hours. Consistent format across releases.

4. Bug Report Follow-Up

The problem: Some bug reports lack critical info (stack traces, reproduction steps, environment). Without it, debugging is a guessing game.

The solution: Claude Code identifies incomplete bug reports and leaves a template comment requesting missing information.

The result: Reporters get helpful guidance. Your team gets the info it needs to fix bugs faster.

5. Dependency Update Notifications

The problem: A critical security patch for a dependency is released. You need to update it and notify the team.

The solution: Claude Code creates an issue automatically, summarizing the vulnerability and update steps. Your CI runs the upgrade, tests it, and opens a PR.

The result: Security updates are tracked and visible. No more forgotten patches.

Hands-on Practice: Four Examples

Example 1: Verify GitHub Access

Terminal/PowerShell

Step 1: Check if you're logged in:

gh auth status

If not logged in: Run gh auth login and follow the prompts to authenticate.

Step 2: View the current repo:

gh repo view

What you should see: Repository details (name, description, URL).

Checkpoint GitHub CLI is authenticated and working.

Example 2: Read Issues and PRs (Read-Only)

Claude Code chat panel

Step 1: Ask Claude to list recent activity:

Prompt
Using the gh CLI, list the 5 most recent pull requests in this repo
(sorted by updated date, most recent first). For each, give me:
1. PR number and title
2. Author
3. Status (open/merged/closed)
4. When it was last updated

What you'll see: A real list of PRs from GitHub. Claude reads live data.

Checkpoint Claude successfully queried GitHub and presented structured results.

Example 3: Draft a GitHub Issue (No Write Yet)

Claude Code chat panel

Step 1: Ask Claude to draft, not create, an issue:

Prompt
Draft a GitHub issue (don't create it yet) with the following:
- Title: "W2D0 GitHub Automation Test"
- Body: A short paragraph explaining this is a training exercise and safe to delete
- Labels: ["documentation", "test"]

Show me the exact content you would create. I'll review it and approve before posting.

What you should see: Claude shows you the exact issue content, without creating it on GitHub yet.

Checkpoint You've reviewed the draft and confirmed the content before it's public.

Example 4: Create an Issue (With Approval)

Claude Code chat panel

Only proceed if you have write access to the repo and are comfortable creating a test issue.

Step 1: Based on your review in Example 3, explicitly approve:

Prompt
I've reviewed the draft and it looks good. Go ahead and create the GitHub
issue with those exact details using `gh issue create`.

Step 2: Claude runs gh issue create and the issue appears on GitHub.

Step 3: Verify it was created:

gh issue list --limit 1

What you should see: Your new test issue listed.

Step 4: Now close it to clean up:

Prompt
Close the "W2D0 GitHub Automation Test" issue using `gh issue close`.
Checkpoint You've created and closed a GitHub issue through Claude Code. Workflow complete.

Key learning: Always draft first, review, approve explicitly. Don't let Claude post without confirmation.

Checkpoint The draft-then-approve pattern here is the same approval-gate discipline from Week 2 Day 1 Topic 03 — a write action gets a look before it fires, every time.
