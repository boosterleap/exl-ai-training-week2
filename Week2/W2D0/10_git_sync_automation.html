Automated git sync — keeping local and remote honest without manual ceremony

Different from Topic 09: this is about your own local repo hygiene, not GitHub's issue/PR layer.

Concept

"Git sync automation" means using a hook (Topic 06) to commit — and optionally push — automatically at a natural checkpoint, like the end of a Claude Code task, instead of remembering to run git add/commit/push yourself every time.

  • Commit and push are different risk levels. An auto-commit is local and reversible — safe to automate freely. An auto-push changes what your team sees — treat it as an explicit opt-in, never a silent default.
  • The Stop hook is the natural trigger. It fires when Claude Code finishes responding — a clean checkpoint to check git status and commit anything meaningful, before the next task starts and the diff gets harder to describe well.
  • Commit message quality still matters even when it's automatic. A hook-generated commit that just says "auto-commit" is worse than no automation — have Claude Code write a real, scoped message describing what actually changed.

Hands-on

2Trigger it for real

Make a small, real change (e.g. ask Claude Code to add one bullet point to this file's concept section), and watch what happens once it finishes:

git log --oneline -3
Checkpoint A new commit should exist with a real, specific message — not "auto-commit" — and git status should be clean.
3Confirm push stayed manual
git status
git log origin/main..HEAD --oneline 2>&1 || echo "check your actual branch name"

Your new commit should exist locally but not yet be pushed — confirming the hook respected the commit/push risk boundary.
