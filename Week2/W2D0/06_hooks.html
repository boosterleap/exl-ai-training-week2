Hooks — deterministic code at lifecycle events

A hook is your own code running at a fixed point in Claude Code's loop — not a suggestion in a prompt, an actual guarantee.

Concept

Hooks fire at named lifecycle events — PreToolUse (before a tool call), PostToolUse (after), SessionStart/SessionEnd, UserPromptSubmit, Stop/SubagentStop — and run a script you define, deterministically, every time. They're configured in .claude/settings.json.

  • Pre vs. post. A PreToolUse hook can inspect — and block — a call before it happens. A PostToolUse hook runs after, with the real result in hand: good for logging, redaction, or validating shape.
  • Why a hook beats "just ask the model nicely." A prompt instruction can be forgotten under context pressure. A hook runs every single time, unconditionally — the same reliability argument behind every guardrail in Week 2.

Hands-on

1Add a real PreToolUse logging hook
Claude Code chat panel
Prompt
Add a PreToolUse hook in .claude/settings.json that appends a one-line
JSON log entry (timestamp, tool name) to W2D0/outputs/tool_log.jsonl every
time any tool is about to be called. Show me the hook config and the small
script it runs.

Trigger a couple of tool calls (e.g. read any file), then check:

cat W2D0/outputs/tool_log.jsonl
Checkpoint Real entries, one per tool call, written without you doing anything except using Claude Code normally.
2PostToolUse, for contrast
Prompt
Now add a PostToolUse hook that, specifically for Read calls, appends how
many characters were read to the same log line. Trigger it and show me the
difference from the Pre-only entries above.
Debrief PreToolUse ran before the result existed — good for deciding whether a call happens. PostToolUse ran after, with real data — good for what you do with what came back. This is exactly what powers Week 2 Day 4's local trace analyzer.
3A blocking hook
Prompt
Add one more PreToolUse hook that BLOCKS any Bash command containing the
string "rm -rf" outright, before it runs. Try to trigger it with a
deliberately scary (but never-actually-run) example command and confirm it
gets refused.
