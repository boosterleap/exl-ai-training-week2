Plugins — packaging skills/commands/agents for distribution

Concept

A plugin bundles skills, commands, agents, and hooks into one installable, shareable unit — instead of hand-copying config files between machines or teammates, you install (or others install) the plugin.

  • Where they come from. Marketplaces (claude plugin marketplace) host installable plugins; you can also scaffold your own locally.
  • Why this matters for a team. Everything you built in Topics 03–06 (a custom command, a subagent, a hook) could become one shared plugin instead of four separate manual setup steps for every new teammate.

Hands-on

1See what's installed
VM · terminal 
claude plugin list
claude plugin marketplace --help
2Scaffold your own
Claude Code chat panel or terminal 
claude plugin init w2d0-demo-plugin

This scaffolds a new plugin at ~/.claude/skills/w2d0-demo-plugin/. Ask Claude Code to explain the scaffolded structure:

Prompt
Look at what claude plugin init just scaffolded. Explain each file's
purpose, and tell me how you'd add the /summarize-changes command from
Topic 03 into this plugin instead of leaving it as a standalone project
command.
Checkpoint You should be able to name which of Topics 03–06's artifacts (command, subagent, hook) could move into this plugin, and why bundling them helps a teammate who's never seen this repo before.
3Validate it
claude plugin validate ~/.claude/skills/w2d0-demo-plugin
