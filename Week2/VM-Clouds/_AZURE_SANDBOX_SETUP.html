Azure Sandbox Setup

Connect the Week 2 curriculum to a sandbox-admin-provided standalone Azure OpenAI deployment using API-key authentication.

On this page 1. Sandbox limits Where steps run 2. Administrator setup 3. Configure access 4. Verify once 5. Finish safely

1. Sandbox limits

The four-hour clock starts with the sandbox. Reserve the final 20 minutes, stop the sandbox when finished, and allow 15–20 minutes for automated cleanup.
  • Azure resources must remain in East US, East US 2, West US, or West US 2.
  • Global Standard, if used for the model deployment, is a processing type—not a resource region.
  • Use only the assigned subscription and pre-created resource group.

Where to complete each step

Open the repository in VS Code on the Ubuntu VM. Use Terminal → New Terminal to activate the environment and confirm the working folder:

source /home/labuser/venv/bin/activate
cd /home/labuser/Desktop/Persistent_Folder/exl-ai-training-week2-shared/exl-ai-training-week2/Week2
pwd

pwd must end in exl-ai-training-week2/Week2. Edit Week2/.env and run the primer in VS Code. Use the browser only for the training sandbox portal and Azure portal.

2. Sandbox administrator setup

Learners do not provision Azure resources. The sandbox administrator creates one standalone Azure OpenAI S0 resource and a small classroom model deployment in an allowed region.

The sandbox administrator or training portal supplies each learner with:

  • the standalone resource endpoint,
  • an API key,
  • the exact deployment name, and
  • an API-version override only if the installed client requires one.

3. Configure API-key access

The sandboxes are separate. Signing in to the Azure portal does not authenticate the Ubuntu VM. Copy the standalone Azure OpenAI endpoint, deployment name, and API key from the assigned Azure sandbox into the private Week2/.env file on the VM.

In VS Code, add or update these four canonical variables in Week2/.env:

AZURE_OPENAI_API_KEY=PASTE-KEY-1-LOCALLY
AZURE_OPENAI_ENDPOINT=https://YOUR-RESOURCE-NAME.openai.azure.com/
AZURE_OPENAI_DEPLOYMENT=class-mini
AZURE_OPENAI_API_VERSION=
  • Use the exact values from the sandbox details. The deployment value is the deployment name, not necessarily the underlying model name.
  • AZURE_OPENAI_API_VERSION is an optional override in the primer; leave its value blank unless the sandbox administrator or installed client requires a dated version.
  • API-key inference does not require Azure CLI or az login.

If learners have Azure portal access, check the endpoint under the assigned Azure OpenAI resource and the deployment name under its model deployments. If those pages are unavailable or values are missing, contact the sandbox administrator/support contact shown in the training portal.

Keep the key secret. Never print it, paste it into notebooks/chat/screenshots, or commit Week2/.env. Check git status before committing. Report an exposed key immediately so an administrator can rotate it.

4. Verify once with the curriculum primer

  1. In VS Code, open W2D2/W2D2AM/_MICROSOFT_AGENT_FRAMEWORK_PRIMER.ipynb.
  2. Select /home/labuser/venv/bin/python as the notebook kernel.
  3. Run its environment/configuration checks, then its single bounded Azure OpenAI verification example.
  4. Stop after one successful response. Do not run loops, load tests, or repeated agent calls.

The primer reads Week2/.env, validates the standalone *.openai.azure.com endpoint, and intentionally does not display the API key.

Need configuration details? Check the training portal first, then the assigned resource in the Azure portal if access is available. For missing resources, deployments, keys, quota, or permissions, contact the sandbox administrator; the instructor cannot change sandbox configuration.

5. Finish safely

  1. Stop notebooks, applications, and agents that can call the endpoint.
  2. Clear exported shell values: 
    unset AZURE_OPENAI_API_KEY AZURE_OPENAI_ENDPOINT AZURE_OPENAI_DEPLOYMENT AZURE_OPENAI_API_VERSION
  3. If you separately used Azure CLI, run az logout. It is not needed for this API-key exercise.
  4. Keep the shared Week2/.env file; do not print or commit its contents.
  5. Stop the sandbox before the four-hour deadline and allow 15–20 minutes for cleanup.
Done means: callers stopped, shell credentials cleared, optional CLI session logged out, secrets uncommitted, and sandbox stopped.
