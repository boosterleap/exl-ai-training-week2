Skills — packaged, invocable expertise

Week 2 Day 2's isolation spectrum named three levels: skills (in-context), subagents (isolated), agent teams (separate processes). This is the first one, in practice.

Concept

A skill is a packaged set of instructions for a particular kind of task — a checklist, a repo-specific workflow, a review procedure — that Claude Code can load and follow, invoked either automatically (when the task matches) or explicitly by name. Unlike a subagent, a skill runs in your current context — no isolation, no separate session.

  • Skill vs. custom slash command. A slash command is a fixed prompt template you trigger by name. A skill is closer to a reusable procedure Claude Code can recognize it should apply, with its own instructions loaded in — more like handing it a runbook than a canned message.
  • Skill vs. subagent (the real decision point). Use a skill when the task should stay in your current conversation's context — you want the result woven into what you're already doing. Reach for a subagent (Topic 05) specifically when you want isolation — a big, noisy sub-task that shouldn't pollute your main context.

Hands-on

1See what's already available
Claude Code chat panel
Prompt
What skills do you currently have available in this session? List them and
one line on what each is for.
2Watch one get used, in-context

Ask for something that plausibly matches one of the skills you just saw listed (or a general one like reviewing a diff, writing commit messages, or building a visualization, depending on what's available) and watch whether Claude Code explicitly invokes it:

Prompt
Review the changes I made to CLAUDE.md in Topic 02 as if preparing a short
code-review comment. If a skill applies here, use it and tell me which one.
Checkpoint Whether or not a skill fires, you should be able to tell from the transcript — this is exactly the kind of thing to look for when deciding later whether your own repeated task belongs as a skill, a custom command (Topic 03), or a subagent (Topic 05).
3Decide: skill, command, or subagent?
Prompt
I want something that always double-checks any Python file I edit for
missing type hints before considering the edit done. Would you implement
that as a skill, a custom slash command, or a subagent? Justify the choice
against the other two.
