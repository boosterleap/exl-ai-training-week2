Why this underpins all Week 2 labs

The instructor delivery guide (guide/week2_instructor_guide.html) assumes a single learner codebase extended daily: Claude Agent SDK, LangGraph, MCP, Chroma, LangSmith (free tier), and Presidio. Cohort differences are not separate folders — they are a LLM_PROVIDER flag in the repo-root .env. That architecture only works if every notebook and script runs inside the same Python environment.

The Week 2 session manifest states the setup once from the Week2 root: create a venv, install requirements.txt, then register the kernel with display name Python (EXL Week 2). Afternoon labs (uv run python main.py triage "...", MCP servers, RAG indexes) reuse that same env. If a learner opens a notebook with the wrong kernel, they will see ImportError for packages that are already installed — the most common Day 1 support ticket.

Instructor intent Spend the first Day 1 AM bridge (or the PM 16:00 bridge) confirming: (1) uv available, (2) Week2\.venv exists, (3) kernel selected, (4) a one-line import langgraph, pydantic, dotenv succeeds. Everything later in the mastery track (modules 02–17) and every W2D1–W2D5 lab assumes this gate is green.

Beginner Install uv, create the Week2 venv, prove imports

Goal: a learner can install uv, create Week2\.venv, activate it on Windows PowerShell or Ubuntu bash, install from requirements.txt, and verify core packages import. Also understand why the cohort uses uv instead of plain pip alone.

What is uv?

uv is a fast Python package and environment manager from Astral. For Week 2 classroom use we treat it as: (1) a reliable way to create a local venv, and (2) a drop-in replacement for pip install that is dramatically faster when twenty learners install the same large stack (LangGraph, LlamaIndex, Chroma, transformers) at once. You still get a standard .venv directory that VS Code, Cursor, and Jupyter understand.

Why uv vs pip (classroom rationale)

Concernpip + venv aloneuv (Week 2 choice)
Cold install of Week2 requirements Often 5–15+ minutes on campus Wi-Fi Typically much faster; less waiting during Day 1 bridge
Reproducible commands Works, but learners mix pip / python -m pip Document one pattern: uv venv + uv pip install
Running scripts without activating Must activate or use full path uv run python ... uses the project venv automatically
Compatibility Baseline everyone knows Still creates a normal venv; pip-compatible install flags
Teaching tip Say out loud: "uv does not replace Python; it manages environments and installs packages into them." Learners who already know venv + pip transfer immediately.

Prerequisites

  • Windows 10/11 with PowerShell 5.1+ or PowerShell 7+, or Ubuntu / bash (WSL or native Linux)
  • Python 3.11 or newer on PATH (check with python --version or python3 --version)
  • Git clone of EXL-CampusHire available locally
  • Network access to PyPI (or campus mirror configured by IT)

cwd: Week2. Activate the venv on Windows PowerShell or Ubuntu bash. On Windows the activation script is .\.venv\Scripts\Activate.ps1; on Ubuntu it is source .venv/bin/activate. Your prompt should show (.venv).

Ubuntu / bash

# not needed on Linux (ExecutionPolicy is Windows-only)

# Confirm activation

# Expect a path ending in Week2/.venv

# Expect: .../Week2/.venv/bin/python
Execution policy Campus machines sometimes block scripts on Windows. Prefer Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass (session only) over changing machine-wide policy. On Ubuntu/bash this does not apply. Alternatively skip activate and use uv run / full path to .venv\Scripts\python.exe (Windows) or .venv/bin/python (Ubuntu).

Why a named kernel?

Jupyter discovers interpreters via kernelspecs. Installing ipykernel with --name=exl-week2 creates a stable label instructors can say aloud: "Select Python (EXL Week 2)." Without this, learners pick a global Python 3.12 that lacks Week 2 packages — or an old Week 1 env — and burn 20 minutes on false ImportErrors.

Canonical command (session manifest) From Week2 root, after requirements install: uv run python -m ipykernel install --user --name=exl-week2 --display-name="Python (EXL Week 2)"

# Python — first cell when your notebook lives under Week2/ConceptBuilding or a W2Dx session
from pathlib import Path
import os

# Strategy A: notebook already under Week2/ConceptBuilding — keep that cwd
CONCEPT_BUILDING = Path.cwd()
if CONCEPT_BUILDING.name != "ConceptBuilding":
    # Strategy B: notebook under a W2Dx session — walk up to Week2 then into ConceptBuilding
    week2 = Path.cwd()
    while week2.name != "Week2" and week2.parent != week2:
        week2 = week2.parent
    CONCEPT_BUILDING = week2 / "ConceptBuilding"
    os.chdir(CONCEPT_BUILDING)

Office-hours decision tree

When a learner raises their hand during the Day 1 bridge or mid-lab, run this tree in order. Skipping to "reinstall everything" wastes the assessment window.

  1. Ask for the notebook kernel display name. If it is not Python (EXL Week 2), switch and rerun the failing cell.

  5. If .venv is missing or the venv python is locked/corrupt, recreate venv and regenerate the kernelspec (A5 / A11).
  6. Only after env health is green, debug application code, API keys, or path-to-data issues.

Exercise Path-1 — Portable notebook path resolver

Portable resolver you can paste at the top of any Week 2 notebook. Works whether the notebook started in ConceptBuilding or a W2Dx session folder. 

# Python — any Week 2 notebook using kernel Python (EXL Week 2)
from pathlib import Path

def find_week2() -> Path:
    here = Path.cwd().resolve()
    for candidate in [here, *here.parents]:
        if candidate.name == "Week2" and (candidate / "requirements.txt").is_file():
            return candidate
    raise FileNotFoundError("Could not locate Week2 root from " + str(here))

WEEK2 = find_week2()
DATA = WEEK2 / "ConceptBuilding" / "data"

print("DATA:", DATA)
print("fnol exists:", (DATA / "fnol_emails.csv").is_file())

FAQ (fast answers)

Q: Can I use conda instead of uv?
A: Not for this cohort. The instructor guide and session manifest standardize on uv + Week2\.venv so support stays one-path.

Q: Do I need JupyterLab if I use Cursor?
A: No. JupyterLab is optional; ipykernel registration is required either way.

Q: Should each day get its own venv?
A: No. One Week 2 env for D1–D5. Provider differences are .env only.

Q: Where do I put API keys?
A: Module 02 — copy Week2\.env.example to Week2\.env. Never commit secrets.

Q: I pulled new commits and something import-fails.
A: From Week2 run uv pip install -r requirements.txt again, then confirm the notebook still uses Python (EXL Week 2).

Q: Does activation survive closing the terminal?
A: No. Each new PowerShell needs Activate.ps1 (or Ubuntu bash needs source .venv/bin/activate) or use uv run. The Jupyter kernelspec does not need activation — it embeds the venv python path.
