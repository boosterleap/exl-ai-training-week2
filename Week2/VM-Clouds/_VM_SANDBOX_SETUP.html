Ubuntu VM Sandbox Setup

Use the Ubuntu VM and its installed VS Code for Week 2 notebooks and scripts. Keep the repository persistent, credentials separate, and provider sessions short-lived.

1. What the Ubuntu VM is for

Use the Ubuntu VM to run Git, Python, course notebooks, cloud CLIs, and the installed VS Code. Use your Windows browser only for the training portal and cloud consoles.

Never paste or commit secrets. Keep passwords, tokens, and keys out of code, notebooks, Git, chat, screenshots, and command examples.

2. Set up the repository and Week 2 environment

Use the persistent folder and clone the repository

Create the shared Week 2 folder once. If the repository is already present, skip the git clone command.

mkdir -p /home/labuser/Desktop/Persistent_Folder/exl-ai-training-week2-shared
cd /home/labuser/Desktop/Persistent_Folder/exl-ai-training-week2-shared
git config --global credential.helper store
git clone https://github.com/boosterleap/exl-ai-training-week2.git

When Git prompts, use username boosterleap and the PAT supplied privately by the trainer as the password. Do not type the PAT into the clone URL, save it in this guide, or share it.

The fine-grained PAT is restricted to this training repository and is saved on the assigned VM so subsequent pulls do not prompt again. Do not run git init in the shared parent folder; git clone initializes the repository.

Create and activate the shared Python environment

Create the environment once. On later visits, run only the source and cd commands before installing updated requirements.

python -m venv /home/labuser/venv
source /home/labuser/venv/bin/activate
cd /home/labuser/Desktop/Persistent_Folder/exl-ai-training-week2-shared/exl-ai-training-week2/Week2
uv pip install -r requirements.txt

Create and protect .env

cp .env.example .env
chmod 600 .env

Add required values only in Week2/.env. Never display its contents or commit it.

3. Run minimal checks

Run each command from the activated Week2 environment:

pwd
python --version
git status --short
git check-ignore .env
pwd should end in exl-ai-training-week2/Week2, Python should come from /home/labuser/venv, and git check-ignore .env should print .env.

4. Open Week 2 in VS Code

source /home/labuser/venv/bin/activate
cd /home/labuser/Desktop/Persistent_Folder/exl-ai-training-week2-shared/exl-ai-training-week2/Week2
code .

Open the required notebook in VS Code and select /home/labuser/venv/bin/python as its Python interpreter or notebook kernel.

5. Follow the cloud guide for the current lab

Cloud and VM sandboxes are separate. Signing in to an AWS, Azure, or GCP browser sandbox does not automatically authenticate tools or Python code on the Ubuntu VM. Follow the selected provider guide to establish VM-compatible access.

Start only the provider sandbox needed for the exercise:

  • AWS sandbox guide
  • Azure sandbox guide
  • GCP sandbox guide

Use only the assigned learner account and the authentication method in the selected guide.

6. Minimal cleanup

  1. Save work in the persistent Code Vault repository.
  2. Save notebooks and close VS Code.
  3. Run git status --short and confirm no secret files are tracked.
  4. Run deactivate.
  5. After the final training session, remove the saved Git credential with rm -f ~/.git-credentials and git config --global --unset credential.helper.
  6. Stop the active cloud sandbox and then the VM through the training portal.
Cloud sandbox cleanup deletes cloud resources. Keep reusable, non-secret work in the persistent repository.
