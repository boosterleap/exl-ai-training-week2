GitHub operations automation

Claude Code drives the gh CLI directly — reading, triaging, and (with your approval) creating issues, PRs, and reviews.

Concept

Claude Code doesn't need a special GitHub integration — gh, the official GitHub CLI, is just another command it can run. If gh auth status shows you're logged in, Claude Code can read issues/PRs, open new ones, comment, and run reviews, all through normal Bash calls it already knows how to make.

  • Read operations are always safe to explore freely — listing issues/PRs, viewing a diff, checking CI status. Write operations (creating an issue/PR, commenting, merging) are real and visible to your team — treat them the way Week 2 treats any irreversible action: confirm the exact content before it goes out.
  • This is exactly the "actions visible to others" category from how you should generally work with any agent — an opened issue or a pushed PR is not private scratch work.

Hands-on

1Confirm access, read-only
VM · terminal 
gh auth status
gh repo view --json name,description,defaultBranchRef
2Have Claude Code triage, read-only
Claude Code chat panel
Prompt
Using gh, list the 5 most recently updated open issues (or pull requests,
if there are no issues) in this repo, and give me a one-line triage note
for each: what it's about and roughly how urgent it looks.
If the repo has no issues/PRs yet That's fine — ask Claude Code to run gh issue list/gh pr list and confirm it correctly reports zero, rather than guessing.
3A real write — only on a repo you control

If you have write access to a repo you're comfortable creating a test issue on (not a shared production repo), try:

Prompt
Draft (don't create yet) a GitHub issue titled "W2D0 test issue — safe to
close" with a one-paragraph body explaining it's a training exercise. Show
me the exact title and body before you run gh issue create.

Review what it drafted, then explicitly approve before it actually runs gh issue create. Close/delete the test issue afterward.

Checkpoint The draft-then-approve pattern here is the same approval-gate discipline from Week 2 Day 1 Topic 03 — a write action gets a look before it fires, every time.
