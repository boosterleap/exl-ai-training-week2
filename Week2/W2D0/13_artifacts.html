Artifacts — publishing a shareable page directly from Claude Code

The last foundational topic before the capstone — and you'll use this exact capability for the Streamlit demo's write-up.

Concept: Artifacts — Shareable Web Pages

The Big Picture

An artifact is a hosted, rendered web page Claude Code publishes for you. No server setup, no deployment, no hosting costs. Just ask Claude to create a dashboard, report, or demo page, and it publishes automatically with a shareable link.

Artifact vs. File

File (in your repo): Code, text, data. You and your team read it in an editor. It's source, not presentation.

Artifact (hosted page): Rendered, styled, interactive. You share a link with stakeholders. They open a browser, see a polished page. No editor, no setup, no technical knowledge needed.

Types of Artifacts

  • HTML dashboards: Real-time data display, charts, interactive controls
  • Documentation: Guides, reports, tutorials—nicely formatted and shareable
  • Demo pages: Show off a feature or idea to non-technical stakeholders
  • Markdown documents: Formatted text, much nicer than raw markdown files
  • Data visualizations: Charts, graphs, heatmaps—all interactive

Sharing and Privacy

Artifacts start private. Only you can see the link. You control whether to share it further.

Update in place: Republish to the same artifact URL to push updates. No new links, just new content.

Self-contained: All CSS, JS, and content are embedded. No external CDN dependencies or broken links.

Real-World Use Cases

1. Project Status Dashboards

The problem: You want to show your team a real-time status dashboard: build status, test coverage, deployment history. Setting up a real server is overkill.

The solution: Claude Code creates a simple HTML page with charts and current metrics. Publish as an artifact.

The result: Dashboard is live in seconds. Shareable link to your team. Update it anytime by republishing.

2. Customer-Facing Reports

The problem: Monthly report to a client. Needs to be pretty, professional, no technical jargon. Can't send a Python script.

The solution: Claude Code generates a polished HTML report with charts, summary, key metrics. Publish as an artifact and share the link.

The result: Professional, self-contained report. Client sees it in their browser, no setup needed.

3. Feature Demo to Stakeholders

The problem: You've built a cool feature. Non-technical stakeholders need to see it working, but your dev environment isn't public.

The solution: Create a demo page in an artifact showing the feature in action.

The result: Stakeholders see a working demo. Their buy-in is faster.

4. Documentation and Guides

The problem: Onboarding docs in markdown. They're hard to navigate, ugly, not indexed.

The solution: Generate as an artifact. It's styled, searchable, shareable.

The result: Better documentation experience. Less friction for new team members.

5. Data Visualization

The problem: You have data (CSV, JSON). You want an interactive visualization without writing D3 or learning Matplotlib.

The solution: Claude Code creates a chart artifact with interactivity built-in.

The result: Beautiful, interactive visualization in minutes.

Hands-on Practice: Two Examples

Example 1: Publish a Summary Artifact

Claude Code chat panel

Step 1: Ask Claude to create and publish a summary artifact:

Prompt
Create a clean, one-page HTML artifact that summarizes everything we've
learned in W2D0 (Topics 01-13). Include a title, a short intro, and a list
of all 13 topics with one-line descriptions. Style it professionally with
a nice color scheme. Then publish it as an artifact and give me the link.

What you'll see: Claude creates HTML and publishes it. You get a link to the artifact.

Checkpoint You have a live artifact link. Visit it in a browser to see your published page.
