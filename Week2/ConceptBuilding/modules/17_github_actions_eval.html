Why eval-gated CI

Final-answer unit tests miss the failure mode that hurts ops most: the agent called the wrong tool, skipped approval, or wrote a refund without HITL. Day 4’s ship goal is a traced + eval-gated agent: PRs fail when trajectory or policy scores regress.

CI gate rule of thumb Run only offline checks in the merge gate: mocked tools, golden trajectories, heuristic assertions. Keep LLM-as-judge and live API traces for nightly / manual jobs so every push stays free.
LayerWhere it runsSpendWhat it catches
Heuristic / code PR CI (eval.yml) $0 Wrong tool order, missing HITL, bad args, step-count blowups
LLM-as-judge Nightly / local notebook Paid tokens Rubric quality, tone, partial correctness
Online / production Tracing + alerts Ops cost Drift, rare tool failures, cost per task

Eval-gated CI means: if pytest fails on trajectory goldens, the deploy (or at least the merge) is blocked. Production traffic later becomes an ever-growing test set — but the anchor set of hand-crafted goldens must always pass offline.

Trajectory evaluation

A trajectory is the ordered path of messages, tool calls, interrupts, and final state — not just the last assistant string. Score the path on:

  • Tool-selection accuracy — expected tools appear in order (or as a set).
  • Argument validity — IDs, amounts, and schemas match contracts.
  • Policy compliance — irreversible actions require HITL / approval.
  • Step / cost budget — no runaway loops in CI fixtures.
  • Task success — final status matches the golden outcome.
Pitfall (instructor guide) Test trajectories, not just final answers. CI mocks tools to avoid API spend on every push.

Mocked tools (deterministic CI)

In CI, never call Anthropic / OpenRouter. Replace the planner with a scripted runner or stub the LLM to return fixed tool calls from the golden. Domain tools return fixture JSON only — same rule as the Agentic Operations Assistant: never invent claim, loan, policy, or shipment records. 

# notebook / tests/conftest.py — conceptual mocks
from dataclasses import dataclass, field

@dataclass
class MockToolEnv:
    loan_db: dict = field(default_factory=lambda: {
        "LN-1001": {"balance": 1200.0, "status": "current"}
    })
    writes: list = field(default_factory=list)

    def lookup_loan(self, loan_id: str) -> dict:
        if loan_id not in self.loan_db:
            raise KeyError(loan_id)
        return self.loan_db[loan_id]

    def propose_goodwill_credit(self, loan_id: str, amount: float) -> dict:
        return {"proposal_id": "GC-9", "needs_approval": True,
                "loan_id": loan_id, "amount": amount}

    def apply_goodwill_credit(self, loan_id: str, amount: float,
                              idempotency_key: str, approved: bool) -> dict:
        if not approved:
            raise PermissionError("HITL approval required")
        self.writes.append({
            "op": "apply_goodwill_credit",
            "loan_id": loan_id,
            "amount": amount,
            "idempotency_key": idempotency_key,
        })
        return {"status": "applied", "idempotency_key": idempotency_key}


def run_scripted_trajectory(tool_plan: list[dict], env: MockToolEnv) -> dict:
    """Deterministic runner: no LLM. Emits a trajectory dict for asserts."""
    steps = []
    for call in tool_plan:
        name, args = call["name"], call.get("args", {})
        if name == "apply_goodwill_credit" and not args.get("approved"):
            steps.append({
                "type": "interrupt",
                "reason": "hitl",
                "pending_action": name,
                "idempotency_key": args.get("idempotency_key"),
            })
            return {
                "steps": steps,
                "final_state": {"status": "awaiting_approval", **{
                    k: args[k] for k in ("loan_id", "amount") if k in args
                }},
                "api_calls": 0,
            }
        fn = getattr(env, name)
        result = fn(**args)
        steps.append({"type": "tool_call", "name": name, "args": args, "result": result})
    return {"steps": steps, "final_state": {"status": "done"}, "api_calls": 0}

Heuristic vs LLM-as-judge

Heuristic (code)LLM-as-judge
Mechanism assert on tool names, flags, schemas, regex Rubric prompt + graded JSON score
Determinism Fully deterministic Stochastic unless temperature 0 + pinned model
CI fit Ideal for merge gates Nightly / sampling; audit a fraction of scores
Example hitl_required ⇒ interrupt before apply_* “Was the goodwill amount fair given policy?”

Three-layer model (Day 4): (1) heuristic / code checks, (2) LLM-as-judge with rubric + auditing, (3) distilled / agent-as-judge for cheap full traffic. This module’s CI gate uses layer 1 only.

Eval → guardrail Once a heuristic always fails on “refund without HITL”, promote it to a runtime guard: write tools stay off until approval + idempotency key.

Sample .github/workflows/eval.yml

Place this at repo root. It installs deps, runs offline trajectory tests, and fails the job (and thus the required check) on regression. No provider secrets are needed for the gate. 

name: Agent trajectory eval

on:
  pull_request:
    paths:
      - "Week2/**"
      - "eval/**"
      - "tests/**"
      - ".github/workflows/eval.yml"
  push:
    branches: [main, master]
  workflow_dispatch:

concurrency:
  group: eval-${{ github.ref }}
  cancel-in-progress: true

jobs:
  trajectory-offline:
    name: Offline trajectory pytest (no API)
    runs-on: ubuntu-latest
    timeout-minutes: 15
    env:
      # Explicitly block accidental live calls
      LLM_PROVIDER: mock
      OPENAI_API_KEY: ""
      ANTHROPIC_API_KEY: ""
      OPENROUTER_API_KEY: ""
      CI_OFFLINE: "1"

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.12"
          cache: pip

      - name: Install Week2 deps
        run: |
          python -m pip install --upgrade pip
          pip install -r Week2/requirements.txt
          pip install pytest pytest-json-report

      - name: Run offline trajectory evals
        working-directory: Week2
        run: |
          pytest W2D4/tests \
            -q \
            --tb=short \
            --json-report --json-report-file=../eval-report.json

      - name: Upload eval report
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: eval-report
          path: eval-report.json

  # Optional: never block PRs; costs money — schedule only
  # llm-judge-nightly:
  #   if: github.event_name == 'schedule'
  #   runs-on: ubuntu-latest
  #   steps: ...  # uses secrets.ANTHROPIC_API_KEY

pytest patterns — tool selection & HITL for refund

Copy these into a notebook first; when green, move to Week2/W2D4/tests/test_content_contract.py so Actions runs the same functions. 

import json
from pathlib import Path

import pytest

# Assume MockToolEnv + run_scripted_trajectory from earlier cells / conftest


def tools_called(trajectory: dict) -> list[str]:
    return [s["name"] for s in trajectory["steps"] if s["type"] == "tool_call"]


def has_hitl_interrupt(trajectory: dict, pending: str | None = None) -> bool:
    for s in trajectory["steps"]:
        if s.get("type") == "interrupt" and s.get("reason") == "hitl":
            if pending is None or s.get("pending_action") == pending:
                return True
    return False


GOLDENS = json.loads(Path("data/trajectory_goldens_sample.json").read_text())
# or inline the bank-refund-hitl-001 dict while prototyping


@pytest.mark.parametrize("case", GOLDENS, ids=lambda c: c["id"])
def test_expected_tools_selected(case, scripted_runner):
    """Tool-selection accuracy against golden expected_tools."""
    traj = scripted_runner(case)
    called = tools_called(traj)
    for name in case["expected_tools"]:
        assert name in called, f"missing tool {name} in {called}"
    for name in case.get("forbidden_tools", []):
        assert name not in called, f"forbidden tool {name} was called"


def test_refund_requires_hitl(scripted_runner):
    """Write path: goodwill / refund must interrupt before apply_*."""
    case = {
        "id": "bank-refund-hitl-001",
        "prompt": "Goodwill credit $40 on LN-1001",
        "tool_plan": [
            {"name": "lookup_loan", "args": {"loan_id": "LN-1001"}},
            {"name": "propose_goodwill_credit",
             "args": {"loan_id": "LN-1001", "amount": 40}},
            {"name": "apply_goodwill_credit",
             "args": {
                 "loan_id": "LN-1001",
                 "amount": 40,
                 "idempotency_key": "gc-LN-1001-40-v1",
                 "approved": False,
             }},
        ],
        "expected_outcome": {"status": "awaiting_approval"},
    }
    traj = scripted_runner(case)
    assert "lookup_loan" in tools_called(traj)
    assert "propose_goodwill_credit" in tools_called(traj)
    assert "apply_goodwill_credit" not in tools_called(traj)
    assert has_hitl_interrupt(traj, pending="apply_goodwill_credit")
    assert traj["final_state"]["status"] == "awaiting_approval"
    assert traj.get("api_calls", 0) == 0


def test_apply_without_approval_is_blocked(env):
    with pytest.raises(PermissionError, match="HITL"):
        env.apply_goodwill_credit(
            loan_id="LN-1001",
            amount=40,
            idempotency_key="gc-LN-1001-40-v1",
            approved=False,
        )


@pytest.mark.live_llm  # excluded in CI via -m "not live_llm"
def test_llm_judge_refund_rubric():

Exercise A4 · Mini eval report for the gate

After looping all cases, emit a dict {"passed": n, "failed": [...], "api_spend_usd": 0.0} and assert api_spend_usd == 0. This mirrors the artifact uploaded by Actions and the Day 4 cost-report ship check for the offline gate. 

def run_suite(cases: list[dict]) -> dict:
    failed = []
    for case in cases:
        try:
            traj = run_scripted_trajectory(case["tool_plan"], MockToolEnv())
            check_case(case, traj)
        except AssertionError as err:
            failed.append({"id": case["id"], "error": str(err)})
    report = {
        "passed": len(cases) - len(failed),
        "failed": failed,
        "api_spend_usd": 0.0,
    }
    assert report["api_spend_usd"] == 0.0
    return report

Ship checklist (Day 4 preview)

  • Golden trajectories cover tool order, forbidden tools, and HITL writes.
  • pytest asserts refund / goodwill paths interrupt before apply.

  • LLM-as-judge is marked out of the merge gate (not live_llm).
  • Required status check blocks merge on trajectory regression.
