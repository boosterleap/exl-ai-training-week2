AWS Bedrock sandbox learner runbook

Authenticate, confirm the sandbox identity, set the approved model target, run one curriculum verification, and clean up.

On this page 1. Sandbox limits Where commands run 2. Authenticate 3. Check identity 4. Set the target 5. Verify once 6. Clean up

1. Start with the sandbox limits

Region

us-east-1 only

Keep the console and every command in US East (N. Virginia).

Lifetime

4-hour automatic cleanup

Stop by 3 hours 30 minutes. Stopping starts cleanup, which usually blocks access for 15–20 minutes.

Do not provision resources. Use the assigned sandbox only, make one bounded inference request, and never place credentials in .env, code, chat, screenshots, or Git.

Run commands on the Ubuntu VM

Open the repository in VS Code, select Terminal → New Terminal, and run every command block below in that Ubuntu terminal:

source /home/labuser/venv/bin/activate
cd /home/labuser/Desktop/Persistent_Folder/exl-ai-training-week2-shared/exl-ai-training-week2/Week2
pwd

pwd must end in exl-ai-training-week2/Week2. Use the browser only for the training sandbox portal and AWS console.

2. Authenticate with supplied temporary credentials

The sandboxes are separate. An AWS console or AWS CloudShell session does not authenticate the Ubuntu VM. The VM requires its own short-lived access key, secret access key, and session token (or another administrator-approved VM credential process).

In the VS Code terminal, use this flow only when the training portal supplies a temporary access key, secret key, and session token. Hidden prompts keep values off-screen and out of shell history.

unset AWS_ACCESS_KEY_ID AWS_SECRET_ACCESS_KEY AWS_SESSION_TOKEN AWS_PROFILE
read -rsp "Temporary access key ID: " AWS_ACCESS_KEY_ID; echo
read -rsp "Temporary secret access key: " AWS_SECRET_ACCESS_KEY; echo
read -rsp "Temporary session token: " AWS_SESSION_TOKEN; echo
export AWS_ACCESS_KEY_ID AWS_SECRET_ACCESS_KEY AWS_SESSION_TOKEN
export AWS_REGION=us-east-1 AWS_DEFAULT_REGION=us-east-1 AWS_PAGER=""
Follow the exact credential type and sign-in instructions shown in the sandbox portal. If it does not supply all three temporary values above, stop and contact the sandbox administrator/support contact for a VM-compatible credential method. Do not copy CloudShell credential files, and do not combine or invent authentication flows.

3. Confirm identity and region

test "$AWS_REGION" = "us-east-1" && aws sts get-caller-identity --region us-east-1

Confirm the account and role match the sandbox details shown in the browser. If either is unexpected, do not invoke Bedrock; clear the variables and contact the sandbox administrator.

4. Obtain BEDROCK_MODEL_ID

Use the exact model ID, inference-profile ID, or ARN supplied by the sandbox administrator. If instructed to discover it, list visible targets in the VS Code terminal and have the administrator confirm the invocation target—never guess a suffix or regional prefix.

aws bedrock list-foundation-models \
  --region us-east-1 \
  --query 'modelSummaries[?modelLifecycle.status==`ACTIVE`].[modelId,modelName,inferenceTypesSupported]' \
  --output table

In VS Code, open Week2/.env (copy .env.example if needed) and set only these canonical values:

AWS_REGION=us-east-1
BEDROCK_MODEL_ID=<exact admin-approved target>
BEDROCK_TIMEOUT_SECONDS=60
BEDROCK_MAX_TOKENS=256

AWS credentials do not belong in Week2/.env.

5. Run one curriculum verification

From the VS Code terminal at the Week2 root, run the existing bounded gateway once. It pins us-east-1, disables automatic retries, and makes one Converse request.

uv run --env-file .env python W2D2/W2D2PM/d2pmt4c03_bedrock_gateway.py

Success prints a classification, deterministic authorization decision, usage, provider request ID, and latency. Do not rerun merely to change model wording. Review the curriculum script rather than copying a separate smoke-test program.

Need command details? Run aws help, aws sts help, or aws bedrock help in the Ubuntu terminal. For identity, access, model availability, or permission issues, use the sandbox administrator/support contact in the training portal.

6. Unset, log out, and stop

unset AWS_ACCESS_KEY_ID AWS_SECRET_ACCESS_KEY AWS_SESSION_TOKEN
unset AWS_PROFILE AWS_DEFAULT_PROFILE AWS_REGION AWS_DEFAULT_REGION AWS_PAGER
unset BEDROCK_MODEL_ID BEDROCK_TIMEOUT_SECONDS BEDROCK_MAX_TOKENS
  1. Close the terminal and log out of the AWS console.
  2. Choose Stop Sandbox in the training portal and confirm.
  3. Do not restart the sandbox to watch cleanup.
