Ubuntu VM Sandbox Setup

Use the Ubuntu VM and its installed VS Code for Week 2 notebooks and scripts. Keep the repository persistent, credentials separate, and provider sessions short-lived.

Guide home Purpose Setup Checks VS Code Cloud guides Cleanup

1. What the Ubuntu VM is for

The VM is where Claude Code lives — it's already installed in VS Code (extension + CLI) and already logged in via subscription. Claude Code, driven from this VM, is the primary hands-on tool for the entire week; the VM also runs Git, Python, and the cloud CLIs needed for the one AWS exercise. Use your Windows browser only for the training portal and cloud consoles — never for running code.

Never paste or commit secrets. Keep passwords, tokens, and keys out of code, files, Git, chat, screenshots, and command examples.

2. Set up the repository and environment

Use the persistent folder and clone the repository

Create the shared folder once. If the repository is already present, skip the git clone command.

mkdir -p /home/labuser/Desktop/Persistent_Folder/exl-ai-training-week2-claude
cd /home/labuser/Desktop/Persistent_Folder/exl-ai-training-week2-claude
git config --global credential.helper store
git clone <REPO-URL-CONFIRMED-BY-TRAINER> .
Confirm the exact clone URL and any PAT with your trainer before Day 1 — it is not filled in here on purpose, since the hosting location for this cohort's repo should be confirmed rather than guessed. Do not type a PAT into the clone URL itself, save it in this guide, or share it; use a stored credential helper as shown.

Activate the pre-installed environment — do not create a new one

The VM's Python environment for this course is a conda environment named ai_agent_env, already populated with everything the week's exercises need (LangGraph, CrewAI, MCP, python-a2a, LanceDB, boto3, and more). Do not run python -m venv or build a separate environment — activate the existing one:

conda activate ai_agent_env
python --version
claude --version
claude auth status
base is the conda environment active by default on a fresh terminal and is not the right one — it's missing almost every course package. Always run conda activate ai_agent_env first, every session.

If a package genuinely appears to be missing from ai_agent_env (confirmed missing before Day 1: sentence-transformers, diskcache, psycopg2-binary, redis, neo4j, presidio-analyzer, presidio-anonymizer, pytest, mlflow), install it into that same environment once, before Day 1:

conda activate ai_agent_env
uv pip install sentence-transformers diskcache psycopg2-binary redis neo4j presidio-analyzer presidio-anonymizer pytest mlflow

No .env file is required this cohort

Claude Code needs no API key (it's already logged in via subscription). The one place this week that does need a secret — the AWS Bedrock exercise in Day 2 PM — exports its key directly into the terminal session for that one command and never writes it to a file. See the AWS sandbox guide when you reach that exercise.

3. Run minimal checks

Run each command from a terminal with ai_agent_env active:

conda activate ai_agent_env
pwd
python --version
claude auth status
git status --short
Python should report from inside ai_agent_env (check with which python — the path should contain ai_agent_env, not base), and claude auth status should show "loggedIn": true. If either is wrong, stop and get the instructor before Day 1 starts.

4. Open the repo in VS Code

conda activate ai_agent_env
cd /home/labuser/Desktop/Persistent_Folder/exl-ai-training-week2-claude
code .

Open the Claude Code panel in VS Code (or use the claude CLI in the integrated terminal) — this is the tool you'll use for essentially every hands-on exercise this week. There are no Jupyter notebooks to select a kernel for in this cohort's materials; everything is a plain .py script run from the terminal or driven directly through Claude Code.

5. Cloud sandboxes — only one is hands-on this week

Cloud and VM sandboxes are separate. Signing in to an AWS, Azure, or GCP browser sandbox does not automatically authenticate tools or Python code on the Ubuntu VM. Follow the selected provider guide to establish VM-compatible access.
  • AWS sandbox guide — hands-on, learners complete this themselves for the Day 2 PM Bedrock exercise.
  • Azure sandbox guide — instructor-demo only this cohort; learners do not need to complete this.
  • GCP sandbox guide — instructor-demo only this cohort; learners do not need to complete this.
Moving a secret from a cloud sandbox browser to the VM: the two are separate machines with no shared clipboard. Use syncclip.in — open it in the cloud sandbox browser tab, paste the value in, note the sync code; open it again in the VM's browser, enter the same code, retrieve the value; paste it into a hidden terminal prompt, never into a file. The AWS guide walks through this step by step at the one point this week it's needed.

6. Minimal cleanup

  1. Save work in the persistent repository.
  2. Close VS Code.
  3. Run git status --short and confirm no secret files are tracked.
  4. Run conda deactivate.
  5. After the final training session, remove the saved Git credential with rm -f ~/.git-credentials and git config --global --unset credential.helper.
  6. Stop the active cloud sandbox (if one is running) and then the VM through the training portal.
Cloud sandbox cleanup deletes cloud resources. Keep reusable, non-secret work in the persistent repository.
