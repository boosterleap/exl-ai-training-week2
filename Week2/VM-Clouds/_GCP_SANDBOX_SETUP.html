Stay inside the sandbox

Four-hour lifetime. Time starts when the sandbox starts. Stop it as soon as you finish; cleanup takes about 15–20 minutes and deletes sandbox resources.
  • Use the sandbox account and exact assigned project ID; never substitute a personal project.
  • Use the location assigned in the sandbox details. The classroom default is global.
  • Use Vertex AI with Google credentials—never an API key or service-account key.
  • Do not create projects, change billing, or alter IAM.

Naming note (current as of July 2026): Google rebranded the Vertex AI console area as the Gemini Enterprise Agent Platform in April 2026 (Cloud Next '26). The underlying APIs (aiplatform.googleapis.com), ADC auth model, and google-adk package are unchanged — only the console navigation label moved. Claude models are also now available directly in this Model Garden alongside Gemini, interesting context for the framework-landscape topic, though this cohort's one hands-on outside-Claude-Code call stays on AWS Bedrock to keep the week bounded.

Command context

Run GCP commands in GCP Cloud Shell

Open the assigned GCP sandbox in the browser, select Activate Cloud Shell in the Google Cloud console, and run every command below — including the venv setup and the Python check — in that Cloud Shell terminal, not your local terminal.

  • GCP Cloud Shell: inspect the sandbox account, select the project, enable/check APIs, set up the demo venv, and test Vertex access.
  • Google Cloud console: check the project selector and APIs & Services → Enabled APIs & services.
  • Your local machine (Windows or the Ubuntu VM): continue normal Week 2 work, but do not assume the separate GCP identity is available there.
No Windows/PowerShell variant needed here. Unlike the Azure guide (which runs in your own local shell), every command on this page runs inside GCP's hosted Cloud Shell, which is always a Linux/bash environment — the same whether your local machine is Windows or the Ubuntu VM. Copy the bash commands below as-is regardless of your local OS.
Step 1

Verify the Cloud Shell identity

Cloud Shell is authenticated by the active GCP sandbox session. Confirm the account and list the projects visible to it:

gcloud auth list
gcloud projects list --format="table(projectId,name)"
Select the assigned sandbox project. Use the exact project ID shown in the sandbox portal. An exlservic-* project is typically the training project; a gen-lang-client-* “Default Gemini Project” is not the Vertex sandbox project.
If the assigned project is absent, stop. Contact the sandbox administrator. Do not use another visible project or change IAM.
Step 2

Pin the project and enable Vertex AI

Copy the exact project ID from the training sandbox details or the project selector at the top of the Google Cloud console. In GCP Cloud Shell, run:

export GOOGLE_CLOUD_PROJECT="REPLACE_WITH_EXACT_ASSIGNED_PROJECT_ID"
gcloud config set project "$GOOGLE_CLOUD_PROJECT"
Reject an inaccessible project. If gcloud says the active account cannot access the project and asks whether to continue, answer n. Return to gcloud projects list and select the exact assigned project ID.

Check whether Vertex AI API is enabled:

gcloud services list --enabled \
  --project="$GOOGLE_CLOUD_PROJECT" \
  --filter="name:aiplatform.googleapis.com"

If this prints Listed 0 items, Vertex AI API is not enabled. Attempt the approved enablement command:

gcloud services enable aiplatform.googleapis.com \
  --project="$GOOGLE_CLOUD_PROJECT"
If enablement returns PERMISSION_DENIED, stop. Contact the sandbox administrator or support contact shown in the training portal. Request that aiplatform.googleapis.com be enabled and that the sandbox identity can use Vertex AI publisher models and consume the service in the assigned project. Ask them to confirm billing/quota and the allowed Gemini model/location. Include the project ID and error text, but no tokens or credentials. The instructor cannot change sandbox IAM or service configuration.

To check in the browser, open Google Cloud console → APIs & Services → Enabled APIs & services, select the assigned project, and search for Vertex AI API.

Step 3

Set up a throwaway environment for the demo

google-adk is not installed in the course's ai_agent_env conda environment (confirmed in the pre-course check) — that's expected, since the rest of Week 2 never needs it. For this exercise, install it into a small scratch venv in Cloud Shell rather than touching the course environment:

python3 -m venv ~/gcp-demo-venv
source ~/gcp-demo-venv/bin/activate
pip install "google-adk>=2.4,<3.0" "google-genai>=2.9,<3.0" "google-auth>=2.38,<3.0"

Set the configuration directly in the shell — no repo .env file needed for this exercise:

export GOOGLE_CLOUD_PROJECT="REPLACE_WITH_EXACT_ASSIGNED_PROJECT_ID"
export GOOGLE_CLOUD_LOCATION=global
export GOOGLE_ADK_MODEL="<sandbox-admin-approved Gemini model>"
export GOOGLE_GENAI_USE_VERTEXAI=true
export GOOGLE_GENAI_USE_ENTERPRISE=true

Do not set GOOGLE_API_KEY or GEMINI_API_KEY — either can route the call away from Vertex AI.

Step 4

Run one minimal check

In Cloud Shell, confirm the identity, project, and Vertex AI API:

gcloud auth list --filter=status:ACTIVE --format='value(account)'
gcloud config get-value project
gcloud services list --enabled \
  --filter='config.name:aiplatform.googleapis.com' \
  --format='value(config.name)' \
  --project="$GOOGLE_CLOUD_PROJECT"

The output must show the assigned sandbox account, the assigned project ID, and aiplatform.googleapis.com. Cloud Shell supplies ADC to Google client libraries; do not run a cross-sandbox login flow or download credential files.

A 403 on the next step indicates missing access; a 404 usually indicates an unavailable model/location; a 429 indicates quota or capacity. Send the exact error and project ID to the sandbox administrator.

Step 5

Run one bounded ADK call, live

No pre-built primer notebook ships in this cohort's materials. A minimal ADK agent call is enough to make the point — write and run it live rather than opening a notebook:

python -c "
from google.adk.agents import Agent
from google.adk.runners import InMemoryRunner

agent = Agent(name='demo_agent', model='$GOOGLE_ADK_MODEL',
               instruction='Answer in one sentence.')
runner = InMemoryRunner(agent=agent)
for event in runner.run(user_id='demo', session_id='demo',
                         new_message='What is the ADK isolation spectrum in one sentence?'):
    if event.content and event.content.parts:
        print(event.content.parts[0].text)
"

Confirm the exact ADK runner API against the installed google-adk version before class — minor API shapes shift between releases; treat this as a starting point to verify once, not a guaranteed-stable snippet. Stop after one successful response.

Need command details? Run gcloud config set --help or gcloud services --help in Cloud Shell. For account, project, API, quota, model, billing, or permission issues, use the sandbox administrator/support contact in the training portal.
Step 6 · Finish before timeout

Revoke and stop

  1. Stop the running script and close Cloud Shell.
  2. Do not revoke or export the sandbox-managed Cloud Shell identity.
  3. rm -rf ~/gcp-demo-venv if the sandbox home directory will persist beyond the exercise.
  4. Stop the sandbox in the portal; allow 15–20 minutes for cleanup.
