Why this layer exists

In Week 2, LangGraph is the orchestrator (state, edges, checkpoints, HITL). langchain-core is the shared vocabulary: message types, tool schemas, and the chat-model interface. Provider packages implement that interface:

PackageRole for this cohort
langchain-core HumanMessage, AIMessage, ToolMessage, @tool, ChatPromptTemplate, Runnable APIs
langchain-openai ChatOpenAI — used for OpenRouter (OpenAI-compatible HTTP API via base_url)
langchain-anthropic ChatAnthropic — direct Claude path when LLM_PROVIDER=anthropic
langgraph Next module — wraps these models in create_react_agent / custom graphs
Mental model Think of langchain as the model + tool adapter. You do not need LangChain agents or LCEL chains for the OpenRouter lab — bind tools on a chat model, then let LangGraph run the ReAct loop. Module 04 chose the provider; this module builds the objects that provider code will invoke.
Offline-first rule Every Beginner and Intermediate exercise runs with zero API calls. Sections marked API stretch need keys in Week2/.env and spend tokens — skip them until you have budget approval.

Beginner Messages & ChatPromptTemplate

LangGraph state almost always stores a list of BaseMessage objects. Roles are typed classes — not free-form dicts — so tool-calling and checkpointing stay consistent across providers.

1. Four message types you will see every day

from langchain_core.messages import (
    SystemMessage,
    HumanMessage,
    AIMessage,
    ToolMessage,
)

messages = [
    SystemMessage(content="You are an FNOL triage assistant. Be concise."),
    HumanMessage(content="Policy POL-1001 reports water damage. Triage please."),
    AIMessage(
        content="",
        tool_calls=[{
            "id": "call_01",
            "name": "lookup_policy",
            "args": {"policy_id": "POL-1001"},
        }],
    ),
    ToolMessage(
        content='{"policy_id": "POL-1001", "status": "active", "deductible": 500}',

for m in messages:
    print(type(m).__name__, "->", repr(m.content)[:60])
TypeWho writes itKey fields
SystemMessage You / graph setup content — persona, lane rules, output contract
HumanMessage Operator / CLI / UI content — user turn
AIMessage Chat model content, optional tool_calls, usage_metadata

2. ChatPromptTemplate — fill slots, keep roles

Templates turn variables into message lists without string-concat bugs. Useful for system prompts that inject lane name, schema JSON, or max-step budgets. 

from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder

prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a {lane} operations assistant. Be factual."),
    MessagesPlaceholder("history"),
    ("human", "{question}"),
])

rendered = prompt.invoke({
    "lane": "banking",
    "history": [HumanMessage(content="Earlier: loan LN-10042")],
    "question": "What is the payoff quote?",
})

# rendered is a ChatPromptValue; .to_messages() → list[BaseMessage]
for m in rendered.to_messages():
    print(type(m).__name__, m.content)

Intermediate Tools, bind_tools, dual providers

3. Defining tools — @tool and Pydantic args

Models only see a JSON schema + description. Your function body is the source of truth for side effects. Prefer explicit Pydantic models when args are more than one or two fields (matches module 03 contracts). 

from pydantic import BaseModel, Field
from langchain_core.tools import tool

class ShipmentLookupArgs(BaseModel):
    shipment_id: str = Field(description="Stable shipment id, e.g. SHP-77")

@tool(args_schema=ShipmentLookupArgs)
def get_shipment(shipment_id: str) -> dict:
    """Return status and hold flag for a shipment id. Read-only."""
    # Offline fake store — no network
    FAKE = {
        "SHP-77": {"status": "on_hold", "hold_reason": "address_verify", "can_release": False},
        "SHP-12": {"status": "in_transit", "eta_days": 2, "can_release": False},
    }
    return FAKE.get(shipment_id, {"status": "not_found", "shipment_id": shipment_id})

print(get_shipment.name)
print(get_shipment.description)
print(get_shipment.args)          # JSON-schema-ish dict for the model
print(get_shipment.invoke({"shipment_id": "SHP-77"}))
Write tools need approval In the PM lab, goodwill credits and hold releases are write operations. Even when you expose them as LangChain tools, the wrapper must check learner approval + idempotency key before mutating. Do not invent claim/loan/shipment records — use fixtures under ConceptBuilding/data/ or an in-memory dict.

5. Tool-calling loop sketch (no LangGraph yet)

This is the algorithm LangGraph ReAct implements for you. Writing it by hand once makes checkpoint / interrupt behavior in module 06 obvious. 

from typing import Callable

TOOL_REGISTRY: dict[str, Callable] = {
    get_shipment.name: get_shipment,
}

def run_one_tool_turn(ai: AIMessage) -> list[ToolMessage]:
    """Execute every tool_call on an AIMessage; return ToolMessages."""
    out: list[ToolMessage] = []
    for call in ai.tool_calls or []:
        fn = TOOL_REGISTRY[call["name"]]
        result = fn.invoke(call["args"])
        out.append(
            ToolMessage(
                content=str(result),
                tool_call_id=call["id"],
                name=call["name"],
            )
        )
    return out

# One ReAct step offline:
history = [
    SystemMessage(content="Use tools before answering."),
    HumanMessage(content="Is SHP-77 releasable?"),
    fake_ai,
]
history.extend(run_one_tool_turn(fake_ai))
# Next: model would see ToolMessage(s) and produce a final AIMessage
print([type(m).__name__ for m in history])

8. Usage metadata — tokens for budgets

OpenRouter / Anthropic paths in the lab read message.usage_metadata after each AI turn to enforce AGENT_MAX_TOKENS and spend knobs from module 02. 

def token_usage(messages) -> tuple[int, int]:
    """Sum input/output tokens from AIMessage.usage_metadata (lab pattern)."""
    inp = out = 0
    for message in messages:
        usage = getattr(message, "usage_metadata", None) or {}
        inp += int(usage.get("input_tokens") or 0)
        out += int(usage.get("output_tokens") or 0)
    return inp, out

# Offline fake AIMessage with usage (no provider call):
ai_with_usage = AIMessage(
    content="Done.",
    usage_metadata={"input_tokens": 120, "output_tokens": 40, "total_tokens": 160},
)
assert token_usage([ai_with_usage]) == (120, 40)

9. Mini ReAct step — fake tools offline, optional provider-backed finish

You now have every piece LangGraph’s ReAct agent uses internally for one tool hop. Assemble a function you could later drop behind a graph node. 

def mini_react_offline(
    question: str,
    tool_choice: dict,
    tools: dict[str, Callable],
) -> list:
    """
    One ReAct hop without a model:
      Human → AI(tool_calls) → ToolMessage(s) → final AI (templated summary).
    tool_choice example:
      {"id": "c1", "name": "get_shipment", "args": {"shipment_id": "SHP-77"}}
    """
    ai = AIMessage(content="", tool_calls=[tool_choice])
    registry = tools
    tool_msgs = []
    for call in ai.tool_calls:
        result = registry[call["name"]].invoke(call["args"])
        tool_msgs.append(
            ToolMessage(content=str(result), tool_call_id=call["id"], name=call["name"])
        )
    summary = AIMessage(
        content=f"Tool {tool_choice['name']} returned: {tool_msgs[0].content}"
    )
    return [
        SystemMessage(content="Prefer tools over guesses."),
        HumanMessage(content=question),
        ai,
        *tool_msgs,
        summary,
    ]

trace = mini_react_offline(
    "Is SHP-77 on hold?",
    {"id": "c1", "name": "get_shipment", "args": {"shipment_id": "SHP-77"}},
    {get_shipment.name: get_shipment},
)
assert [type(m).__name__ for m in trace] == [
    "SystemMessage", "HumanMessage", "AIMessage", "ToolMessage", "AIMessage"
]
print(trace[-1].content)

Pitfalls

  • Mismatched tool_call_id — providers reject or ignore ToolMessages that do not reference the AI’s call id.
  • Calling tools inside the model class — binding ≠ execution. Your code (or LangGraph) must run the function and append ToolMessages.
  • Wrong package for OpenRouter — use langchain-openai’s ChatOpenAI with OpenRouter base_url, not a missing third-party wrapper.
  • Inventing domain records — always tool against fixtures or explicit fakes; never fabricate policy/claim/loan/shipment facts in prose.
  • Write tools without approval — hold release / goodwill credit must gate on learner approval and an idempotency key.
