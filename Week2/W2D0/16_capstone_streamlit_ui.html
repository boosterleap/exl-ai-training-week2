Capstone Stage 3 — Streamlit UI

Stage 2 left you a trained model sitting in a .joblib file — correct, but useless to anyone who isn't comfortable calling model.predict() from a Python shell. This stage directs Claude Code to wrap that model in a small Streamlit app: sliders in, a prediction out, no code required from whoever ends up using it.

Concept

A model that only a developer can run isn't done — it's half-shipped. Streamlit closes that gap with a thin script that turns Python into a browser UI.

  • A trained model is not a deliverable on its own. The stakeholders who care about "what would this house be worth" are not going to open a notebook and call predict(). A UI is what turns a model.joblib file sitting in outputs/ into something a non-technical person can actually use — move a few sliders, click a button, read a number.
  • Streamlit reruns the entire script top to bottom on every interaction. Move one slider, and Streamlit doesn't just re-execute a callback — it re-executes the whole file from line one, including any expensive setup at the top. That's the mental model to hold before writing anything: every widget touch is effectively "run the script again."
  • st.cache_resource exists specifically to survive that rerun model. Without it, a function that loads the model file from disk would fire again on every single slider drag, reopening and deserializing model.joblib dozens of times in a session for no reason. @st.cache_resource tells Streamlit to run the load function once, keep the object alive across reruns, and hand back the cached instance every time after — so the expensive part happens once, not every time a slider ticks.
  • The shape of a Streamlit app is always the same loop: widgets in, state read, action, output. Widgets (st.slider, st.button) declare inputs and hold their current value; you read those values back into a plain dict or dataframe row; a button gates the actual computation so it only happens on demand, not on every rerun; and the result renders with something like st.metric. Once you can name those four parts, most Streamlit apps — this one included — are just filling in the blanks.

Hands-on

1Direct Claude Code to build the Streamlit app
Claude Code chat panel
Prompt
I'm on Stage 3 of the capstone. Stage 2 saved a trained model to
W2D0/capstone/outputs/model.joblib. Build a Streamlit app at
W2D0/capstone/my_app.py that does the following:

1. Loads the model from outputs/model.joblib using joblib, wrapped in a
   function decorated with @st.cache_resource so it's only loaded once per
   session, not on every widget interaction. If the file doesn't exist,
   show an st.error telling me to run train_model.py first and st.stop().
2. Shows a title ("California Housing — median value predictor") and a
   short caption.
3. Lays out one slider per feature for all 8 California Housing features
   (MedInc, HouseAge, AveRooms, AveBedrms, Population, AveOccup, Latitude,
   Longitude), with sensible min/max ranges and a reasonable default value
   for each — split them across two st.columns so it isn't one long list.
4. Has a "Predict median house value" button. On click, build a one-row
   dataframe from the current slider values in the same column order the
   model was trained on, call model.predict() on it, and display the
   result with st.metric. The model's target is in $100k units, so scale
   the raw prediction by 100 and show it as a dollar figure like "$204.9k".

Keep it to one file, no extra pages or session-state complexity — this is
meant to be a small, direct wrapper around the model.

Let Claude Code choose the exact slider ranges and defaults — the important thing is that all 8 features are covered and the column order matches what the model expects. If it asks you what unit the target is in, tell it: the California Housing target is median house value in $100,000s, and the UI should present it as a $k figure for readability.

2Run it and try it in a browser
VM terminal

streamlit is already installed in the ai_agent_env conda environment from Stage 1's setup, so there's nothing extra to install here.

uv run streamlit run W2D0/capstone/my_app.py

Streamlit prints a local URL (typically http://localhost:8501) — open it. You should see the title, the caption, 8 sliders arranged in two columns, and a predict button. Move a couple of sliders and confirm nothing predicts until you actually click the button.

3Compare two contrasting profiles
Predict first Before you touch the sliders, recall Stage 1's correlation heatmap: which feature had the strongest relationship with MedHouseVal? Write down which direction you expect the prediction to move if you push that feature toward its high end versus its low end, holding everything else fixed.

Now try it for real. Set up a "high-income coastal" profile — high MedInc, latitude/longitude near the coast (e.g. around the Bay Area or LA) — click predict and note the value. Then, without touching anything else, drag MedInc down to a low value and predict again. Repeat with a "low-income inland" profile (lower income, longitude further east). Does the swing in predicted value line up with what the Stage 1 heatmap told you about MedInc's correlation with the target?

Debrief This is the same signal from Stage 1's correlation heatmap, just made interactive: if MedInc was the strongest correlate of MedHouseVal, dragging it should move the prediction more than any single other slider. A UI doesn't teach the model anything new — it just makes the relationships you found in EDA tangible enough to poke at.
4Why the rerun model matters here

Ask Claude Code to point out, in the file it just wrote, exactly which line only runs once per session versus which lines rerun on every slider move. It should be able to point at the @st.cache_resource-decorated load function as the one thing that survives reruns, and everything below st.title as re-executing top to bottom every time a widget changes.

Checkpoint The app should show the title "California Housing — median value predictor", a caption, exactly 8 sliders across two columns, and one "Predict median house value" button. Clicking predict with reasonable inputs should render a real number via st.metric — the reference implementation produced $204.9k on its default slider values. This my_app.py is exactly what Stage 4 will exercise headlessly with streamlit.testing.v1.AppTest, so if it runs cleanly here, Stage 4's automated test has something real to check.
