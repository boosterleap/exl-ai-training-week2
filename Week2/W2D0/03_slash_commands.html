Slash commands — built-in and custom

The fastest way to repeat a multi-step instruction without retyping it.

Concept

Built-in commands are typed directly in the chat panel — things like /help, /compact (Topic 07), /agents, /mcp. Custom commands are your own — a markdown file that becomes a reusable, named prompt template, scoped project- or user-wide the same way CLAUDE.md and settings are.

  • Why bother, if you could just type the prompt again? A custom command is versioned (checked into the repo, so your whole team gets it), and can take arguments — turning a paragraph you'd retype every time into /review-pr 142.
  • Project- vs user-scoped, the same pattern as everything else. A command that only makes sense for this repo's conventions belongs at project scope (shared, committed). A command you want in every project you touch belongs at user scope.

Hands-on

1Tour the built-ins
Claude Code chat panel

Type /help and skim what's available. Try /agents (you'll use it for real in Topic 05) and /mcp (Topic 08) just to see their empty-state output for now.

2Have Claude Code build you a real custom command
Prompt
Create a project-scoped custom slash command called /summarize-changes that,
when run, looks at `git diff` for the current working tree and writes a
short, plain-English summary of what changed. Show me exactly what file you
created and where, and explain the project- vs user-scope convention you
used.
What to look for Claude Code should create a markdown file under a project-scoped commands location (not your home directory) and explain how it would differ if you'd asked for a user-scoped one instead.
3Use it

Make a small, harmless edit to any file (e.g. add a blank line somewhere), then run your new command:

Prompt
/summarize-changes
Checkpoint It should describe your actual pending change, not a generic answer — confirming the command is really reading live repo state, not just returning canned text. Revert your throwaway edit afterward (git checkout -- <file>) if you don't want it kept.
