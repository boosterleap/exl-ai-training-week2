Beginner Why this SDK

The Claude Agent SDK wraps the same agent loop that powers Claude Code: gather context → call the model → run tools → repeat, with session memory, permissions, and hooks. You do not hand-roll the tool loop for Day 1 PM.

LayerJobDay 1 PM touchpoint
Runtime ClaudeSDKClient + ClaudeAgentOptions PM provider concept → run_anthropic
Capabilities Built-in tools + in-process MCP domain tools tools.py → build_sdk_mcp_server
Knowledge / rules CLAUDE.md, optional Skills W2D1PM/CLAUDE.md via setting_sources=["project"]
Guardrails allowed_tools, can_use_tool, hooks Logistics write gate; Day 2 hooks demo
Metering max_turns, max_budget_usd, usage on ResultMessage CostLog / budget experiment
Mental model Tools and MCP are verbs (what the agent can do). Skills / CLAUDE.md are manuals (how to do the job). Sub-agents and teams change isolation and coordination — not “more tools.”

Beginner query() vs ClaudeSDKClient

Both entry points take a prompt and ClaudeAgentOptions. They differ in session lifecycle and interactive control.

Featurequery()ClaudeSDKClient
SessionNew session by defaultReuses one session across calls
ConversationSingle exchange (unless resume / continue)Multi-turn in the same context
ConnectionManaged for youYou own connect / disconnect
InterruptsNot supportedSupported
Custom tools & hooksSupportedSupported (preferred for lab UX)
Best forOne-off scriptsPM lab: sessions, permissions, follow-ups

Offline shapes (no network)

# One-off — fire and stream
async for message in query(prompt="Triage claim CLM-424063", options=options):
    print(message)

# Stateful client — PM lab shape
async with ClaudeSDKClient(options=options) as client:
    await client.query("Triage claim CLM-424063")
    async for message in client.receive_response():
        print(message)
    # later, same session:
    await client.query("What was the reserve?")
    async for message in client.receive_response():
        print(message)
Day 1 PM choice providers.run_anthropic uses ClaudeSDKClient so banking can resume, permissions can callback, and traces stay one session. OpenRouter cohorts get the same CLI via LangGraph — same schemas, different runtime.

Intermediate Tools, @tool, in-process MCP

Custom tools are declared with the SDK @tool decorator, then registered on an in-process MCP server via create_sdk_mcp_server. Names surface as mcp__<server>__<tool>.

Decorator sketch (offline)

from typing import Any
# from claude_agent_sdk import tool, create_sdk_mcp_server

@tool("policy_lookup", "Fetch policy metadata by policy id.", {"policy_id": str})
async def sdk_policy_lookup(args: dict[str, Any]) -> dict[str, Any]:
    # Call your domain function — never invent records
    payload = {"found": True, "policy_id": args["policy_id"], "status": "active"}
    return {"content": [{"type": "text", "text": json.dumps(payload)}]}

@tool(
    "release_hold",
    "Queue a shipment hold release. This write requires approval.",
    {"container_id": str, "reason": str, "idempotency_key": str},
)
async def sdk_release_hold(args: dict[str, Any]) -> dict[str, Any]:
    # Write path: idempotency_key required in the PM lab
    ...

ops = create_sdk_mcp_server(
    name="ops",
    version="1.0.0",
    tools=[sdk_policy_lookup, sdk_release_hold, ...],
)
# ClaudeAgentOptions(mcp_servers={"ops": ops}, ...)

Read vs write tools in the lab

KindNamesPolicy
Read policy_lookup, claims_status, loan_lookup, shipment_lookup In allowed_tools → auto-approve
Write apply_goodwill_credit, release_hold Not auto-approved; can_use_tool denies unless --approve-writes; require idempotency key

Message blocks you will see in traces

  • TextBlock — assistant prose
  • ToolUseBlock — name + arguments
  • ToolResultBlock — observation
  • ThinkingBlock — when thinking is enabled
  • ResultMessage — final text / structured output / usage / cost / session_id

Project context: CLAUDE.md

With cwd set to the PM folder and setting_sources=["project"], the SDK loads project instructions from CLAUDE.md. Day 1 PM rules include:

  • Three lanes: insurance / banking / logistics
  • Use domain tools for facts — never invent claim, loan, policy, or shipment records
  • Goodwill credits and hold releases are writes → approval + idempotency key
  • Return a valid TriageDecision; keep summaries operator-facing
Compaction note Long sessions may summarize older turns to free context. Compacted history is lossy — persist durable facts in your own session store / artifacts when they must survive.

Intermediate Permissions

Permission evaluation order (simplified): settings allow rules → allowed_tools / permission mode → can_use_tool callback when the flow would prompt. To gate every tool call regardless of allowlists, use a PreToolUse hook (next section).

can_use_tool sketch (PM logistics gate)

from claude_agent_sdk.types import (
    PermissionResultAllow,
    PermissionResultDeny,
    ToolPermissionContext,
)

WRITE_TOOL_NAMES = {"apply_goodwill_credit", "release_hold"}

async def permission_gate(
    tool_name: str,
    input_data: dict,
    context: ToolPermissionContext,
) -> PermissionResultAllow | PermissionResultDeny:
    short_name = tool_name.rsplit("__", 1)[-1]  # strip mcp__ops__
    if short_name in WRITE_TOOL_NAMES and not approve_writes:
        return PermissionResultDeny(
            message="Write tool blocked. Re-run with --approve-writes.",
            interrupt=False,
        )
    return PermissionResultAllow(updated_input=input_data)
CLIExpected behavior
d1pmt5c02_enforce_write_permission.py Write denied; denial appears in result / permission_denials
... permissions-demo --approve-writes Write allowed; idempotent receipt under outputs/actions/

Advanced Hooks: PreToolUse / PostToolUse / Stop

Hooks run your deterministic code at lifecycle points. The model cannot talk its way past a deny. Python hook events include (among others): PreToolUse, PostToolUse, PostToolUseFailure, Stop, SubagentStart, SubagentStop, UserPromptSubmit, PreCompact, PermissionRequest.

EventUseLab parallel
PreToolUse Validate / transform / deny before execution Block refunds; audit “allowed”
PostToolUse Log results, redact, metrics Record result keys after loan_lookup
Stop Record why the run ended blocked_or_done / max_turns / budget

HookMatcher registration sketch

from claude_agent_sdk import ClaudeAgentOptions, HookMatcher

async def validate_write(input_data, tool_use_id, context):
    name = input_data.get("tool_name", "")
    if name.endswith("release_hold"):
        args = input_data.get("tool_input") or {}
        if not args.get("idempotency_key"):
            return {
                "hookSpecificOutput": {
                    "hookEventName": "PreToolUse",
                    "permissionDecision": "deny",
                    "permissionDecisionReason": "idempotency_key required",
                }
            }
    return {}

async def audit_post(input_data, tool_use_id, context):
    print("PostToolUse", input_data.get("tool_name"))
    return {}

async def on_stop(input_data, tool_use_id, context):
    print("Stop", input_data)
    return {}

options = ClaudeAgentOptions(
    hooks={
        "PreToolUse": [
            HookMatcher(matcher="mcp__ops__release_hold", hooks=[validate_write]),
            HookMatcher(hooks=[lambda *a: {}]),  # all tools no-op example
        ],
        "PostToolUse": [HookMatcher(hooks=[audit_post])],
        "Stop": [HookMatcher(hooks=[on_stop])],
    },
)

Offline handler pattern (Day 2 hooks_demo style)

# No SDK required — pure functions you can unit-test today
DISALLOWED = {"issue_refund"}

def pre_tool_use(tool_name: str, args: dict) -> dict:
    if tool_name in DISALLOWED:
        return {"hook": "PreToolUse", "allowed": False, "audit": "blocked", ...}
    return {"hook": "PreToolUse", "allowed": True, "audit": "allowed", ...}

def post_tool_use(tool_name: str, result: dict) -> dict:
    return {"hook": "PostToolUse", "ok": "error" not in result, "audit": "logged"}

def stop_hook(reason: str, event_count: int) -> dict:
    return {"hook": "Stop", "reason": reason, "events": event_count, "audit": "stopped"}
Permissions vs hooks can_use_tool runs when the permission flow would prompt. Tools already in allowed_tools skip that callback. Use PreToolUse when you need a hard gate on every matching call.

Advanced Isolation spectrum: skills → sub-agents → teams

Pick the primitive by how much context isolation and peer coordination you need — not by how “agentic” the marketing sounds.

PrimitiveIsolationCommunicationSDK / Code surface
Skills Same context window (progressive disclosure) N/A — knowledge loaded into the session .claude/skills/*/SKILL.md, skills=["name"] or "all"
Sub-agents Fresh context per worker; summary returns to parent Parent → child via Agent tool; one-way report back agents={...: AgentDefinition(...)}, include Agent in allowed_tools
Agent teams (experimental) Separate processes / instances Shared task list + direct teammate messaging CLI/feature flag oriented; not a Day 1 PM option knob. Study TeammateIdle / TaskCompleted hooks in TS docs

Day 1 PM stays left of the spectrum Insurance / banking / logistics use one main agent + MCP tools + CLAUDE.md. Sub-agents and teams are Day 2+ concepts — know the spectrum so you do not over-build isolation for a single triage decision.

Advanced Cost metering & hard caps

Treat spend and steps as hard stops you configure, then log what the run actually used.

KnobAnthropic Agent SDKOpenRouter / LangGraph path
Steps max_turns → subtype error_max_turns Graph recursion_limit
Spend max_budget_usd → error_max_budget_usd Track tokens; no identical USD hard stop
Tokens Recorded on ResultMessage; mark exceeded after run if over AGENT_MAX_TOKENS max_tokens per model call
Report total_cost_usd, usage, num_turns Token totals + CostLog fields

CostLog sketch

cost_log = {
    "steps_used": result_message.num_turns,
    "max_steps": settings["max_steps"],
    "input_tokens": usage.get("input_tokens", 0),
    "output_tokens": usage.get("output_tokens", 0),
    "total_tokens": ...,
    "max_tokens": settings["max_tokens"],
    "total_cost_usd": result_message.total_cost_usd,
    "max_budget_usd": settings["max_budget_usd"],
    "stopped_reason": result_message.subtype,  # or token_budget_exceeded
}
2026 metering awareness Client-side total_cost_usd is an estimate compared against max_budget_usd. Always write a cost log even when the provider omits USD — steps and tokens still prove the run stayed inside policy.
